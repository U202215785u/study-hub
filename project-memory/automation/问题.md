# Automation 领域问题记录

## P2: 抖音解析报错 [Errno 22] Invalid argument（2026-06-06）

### 现象
用户解析抖音视频时，后端报错 `[Errno 22] Invalid argument`。报错发生在 `_extract_douyin_raw` 的临时文件创建阶段。

### 根因
`_safe_filename` 函数生成临时文件名时，只替换了 Windows 常见非法字符 `\/:?"<>|`，但漏掉了三类会导致 `Errno 22` 的字符：
1. **Emoji 和装饰符号**——抖音标题里很常见
2. **零宽字符**（零宽空格 `\u200b`、零宽连接符 `\u200d` 等）
3. **Windows 保留名**（CON、PRN、AUX、NUL、COM1-9、LPT1-9）
4. **Unicode 组合字符**——分解形式的字符在 Windows 文件名中可能报错

### 修复
增强 `backend/endpoints/automation.py` 中的 `_safe_filename` 函数：
- 过滤零宽字符和不可见格式字符
- 过滤主要 emoji 区块
- Unicode NFC 规范化
- 防御 Windows 保留名（遇到保留名自动加 `_` 前缀）

### 影响范围
- 直接修复抖音解析
- 间接保护 B 站解析、小红书解析、`_run_claude` 生成 `.md` 文件等所有使用 `_safe_filename` 的路径

### 验证
```
_safe_filename('CON')     → '_CON'
_safe_filename('hello😀')  → 'hello_'
_safe_filename('a\u200bb') → 'ab'
```

### 预防措施
以后任何新增的平台解析或文件生成逻辑，都复用 `_safe_filename`，不要自己手写文件名清理。

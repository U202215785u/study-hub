# Study-Hub 管家入口规则设计

日期：2026-08-01  
状态：已确认，待实施

## 目标

用户在 Codex 中提出项目操作时，不需要知道管家、角色或工具名称。凡是排查故障、改动代码、项目检查、发布或与项目直接相关的研究，处理必须先进入 Study-Hub 管家运行流程。

纯粹解释概念、闲聊和未要求项目行动的讨论不创建任务，也不增加打扰。

## 入口范围

进入管家的请求包括：

- 排查或修复异常；
- 修改、新增或删除项目功能；
- 检查项目状态、健康或测试结果；
- 发布、部署或上线前检查；
- 为当前项目研究外部方案。

不进入管家的请求包括：

- 与当前项目无关的普通问答；
- 单纯解释术语或代码概念；
- 尚未要求调查、检查或改动的想法讨论。

## 处理流程

1. Codex 判断请求属于入口范围后，先创建一项管家任务。
2. 读取该任务当前唯一允许的下一步；在定位、分派、确认、实施、审查和验证之间依次推进。
3. 涉及删除、个人数据、账号权限、发布或其他高影响操作时，必须等待用户明确确认。
4. 实际代码改动必须记录改动、完成检查，并验证用户最初描述的问题是否解决，才能结束任务。
5. 同一路径连续三次未取得进展时，管家停止继续尝试，等待用户给出新方向。

## 职责边界

- 项目设置只规定“何时必须进入管家”，不要求用户选择任何内部角色或领域专家。
- 管家运行底座负责保存任务事实、限制步骤顺序和保存验证证据。
- Codex 仍负责理解自然语言、阅读项目文件和实际执行工作。
- 此阶段不增加阻止文件修改的底层拦截器；若后续仍出现绕过入口的情况，再单独评估更严格的保护措施。

## 验收标准

- 对一条排查、改动、检查、发布或项目研究请求，Codex 会先创建管家任务并读取下一步。
- 对普通概念问答，不会创建任务。
- 高影响操作没有用户确认时不能进入实施。
- 不改变 Study-Hub 原有知识库、复盘、解析等能力。

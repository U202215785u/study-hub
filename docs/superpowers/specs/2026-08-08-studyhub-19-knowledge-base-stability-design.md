# STUDYHUB-19 知识库稳定性设计

## 目标

让每个外部内容源在知识库中只有一个稳定的活动文档；用户能浏览全部文章；重新识别的真实结果、降级结果和失败结果必须被明确区分并可追溯。

## 已确认事实

- 运行数据库是 `study-hub/backend/data/study_hub.db` 的 SQLite `documents` 表，Chroma 是派生检索索引。
- `GET /documents` 默认只返回 50 条，运行库实际有 101 条。
- 文档 #323 与 #324 含相同抖音原链却有不同正文；启动时的孤儿摘要恢复仅按全文哈希或完全相同的标题去重。
- 文章列表目前通过正文关键词推断 `asr_failed`。ASR 不可用时后台会生成降级元数据卡并把任务标为完成，造成“任务已完成、文章仍显示识别失败”的矛盾。

## 设计决策

### 稳定文档身份

为 `documents` 增加 `source_key`、`source_url`、`document_status`、`updated_at`、`asr_status` 和 `asr_error`。对已经解析到视频 ID 的抖音内容，`source_key` 是 `douyin:<video_id>`；尚未解析的历史短链使用独立命名空间 `douyin:short:<short_code>`。短码不是视频 ID，迁移不得把二者猜测为同一个键。

活动文档满足 `document_status = 'active'`。同一 `(source, source_key)` 至多保留一篇活动文档；旧版本和重复项不删除，而是转为 `archived_duplicate`。同一短码或同一长链视频 ID 可以自动合并；历史短码与长链视频 ID 之间的跨命名空间关系进入人工审核清单，不自动合并。新导入和重新识别必须使用解析器返回的视频 ID 写入规范化键与长链 URL。

历史重复归档前不能建立活动文档的部分唯一索引，因此新增 `document_source_claims` 作为新导入的数据库级唯一声明。导入事务先取得或读取该声明，再创建/更新活动文档；历史碰撞只在审核后写入声明。完成归档后，再以部分唯一索引提供最终数据库约束。

### 版本与向量

首次交付不引入完整的文章版本表。迁移时把被归档的原文保留在原记录中，保留 `duplicate_of_document_id` 指向活动文档；活动文档的更新继续原位进行。Chroma 仅索引活动文档，归档时删除相应向量，保留时为活动文档重建向量。

### ASR 状态

`asr_status` 的合法值为 `not_applicable`、`pending`、`processing`、`succeeded`、`fallback`、`failed`。`fallback` 表示资料可读但没有得到可用转写；它不能被显示为成功，也不能被归为运行错误。`asr_error` 只保存安全、可操作的错误说明，不保存 API 密钥、请求头或第三方原始凭据。

复用已有 `task_queue` 作为唯一任务事实来源，新增 `document_id`、`reparse_mode`、`asr_status` 和已消毒的 `asr_error` 字段。文章状态取其最近一次任务结果，正文不再作为状态来源；不新增第二套 `document_processing_attempts` 状态表。`reparse_mode='in_place'` 保留原文，只有新结果有效后才原地更新并重建该文档的向量。

### 全量浏览

新增 `GET /documents/page`，使用不透明 cursor 和 `created_at DESC, id DESC` 的稳定排序。响应为 `{ items, next_cursor, total }`，页面通过“加载更多”访问全部文章。保留旧 `/documents` 数组接口，避免 MCP 和旧调用方突然失效。

### 启动恢复

孤儿摘要恢复先提取 `source_key`；命中活动文档时只更新已知同源记录或跳过，不插入第二篇。不能提取来源键的文件进入恢复审计清单，不自动出现在活动知识库。恢复结果写入可查询审计日志。

## 数据迁移和回滚

1. 在任何状态变更前创建带时间戳的 SQLite 备份，并记录文档数、活动向量数和数据库校验哈希。迁移统一将 `created_at`/`updated_at` 写为 SQLite `YYYY-MM-DD HH:MM:SS`，避免混入 ISO `T` 时间戳破坏游标排序。
2. 先执行 dry-run，输出按 `source_key` 分组的候选清单：保留记录、拟归档记录、是否存在正文差异和无法识别项。
3. 用户审核清单后才执行归档。归档是可逆的：恢复 `document_status` 并重建向量即可。
4. 迁移异常时停止批次，用备份恢复数据库；不执行物理删除。

## 非目标

- 不在本轮清洗中删除原始 Markdown 摘要文件。
- 不为无法确定原链的历史文章猜测或联网补全身份。
- 不把 50 条替换为一次性加载所有文章；全量访问通过稳定分页实现，避免浏览器和数据库一次性加载过多内容。

## 验收标准

- 同一短码或同一长链视频 ID 多次导入只存在一篇活动文档；新导入在解析后统一落为视频 ID。历史短码与长链的跨命名空间候选必须被报告并经审核后再合并。
- 知识库显示总数，并能访问所有活动文章。
- 服务重启不会因孤儿恢复新增同一原链的第二篇活动文档。
- 重新识别页面能清晰显示处理中、转写成功、降级摘要和失败四种结果。
- 搜索、列表和首页最近文档都不显示 `archived_duplicate`。
- 迁移前后的文档和向量数量可核验，且归档可恢复。

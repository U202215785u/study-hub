# Study-Hub 管家任务卡与项目记忆设计

日期：2026-08-01  
状态：用户授权实施

## 目标

管家在完成初步定位后，生成一张可直接交给另一位执行 Agent 的简洁任务卡。任务卡必须引用当前任务已经记录的项目记忆和定位依据，不能把猜测包装成事实。

## 任务卡格式

任务卡固定为五行：

```text
【任务】...
【已知】...
【定位】...
【范围】...
【验收】...
```

`已知` 使用用户原始描述和已确认事实；`定位` 汇总功能代号、项目记忆命中、相关领域文件与补充定位说明。任何缺失内容显示“待查”。

## 数据与交接

- `record_context` 新增可选的项目记忆摘要和补充定位说明，保持原有调用兼容。
- `create_task_card` 要求任务至少完成定位；调用者提供简短的范围与验收标准。
- 生成的卡片保存到该任务的既有 `context` 中，并记录一条交接事件；不增加数据表。
- `get_task_card` 返回已经保存的卡片，方便复制到另一位 Agent 的对话。
- 执行 Agent 的结果仍通过同一个任务编号回交，继续使用既有改动、审查和验证闸门。

## 边界

任务卡不创建新任务、不直接改代码、不替代项目记忆文件。它只是把已定位的任务事实压缩为交接格式。

## 验收

- 任务卡包含五行固定标签。
- 卡片引用项目记忆摘要、功能代号或领域文件时，来源可辨认。
- 缺失定位、范围或验收信息显示“待查”。
- 未完成定位的任务不能生成任务卡。
- MCP 同时提供生成和读取任务卡的能力。

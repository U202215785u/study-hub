# 抖音视频深度总结

当用户发送抖音分享链接时，执行以下流程，输出一份结构化的 Markdown 文档。

## 执行流程

### 第一步：解析视频信息

调用 `mcp__douyin-mcp__parse_douyin_video_info` 获取视频标题、视频ID、下载链接等基本信息。

### 第二步：提取视频文本（三级降级策略）

**Level 1 — 直接 ASR**
调用 `mcp__douyin-mcp__extract_douyin_text` 提取视频中的语音文本。

**Level 2 — 下载音频后识别**
如果 Level 1 因「文件过大」失败：
1. 调用 `mcp__douyin-mcp__get_douyin_download_link` 获取无水印下载链接
2. 用 ffmpeg 提取纯音频（去掉视频轨道，大幅缩小文件）：
   ```bash
   ffmpeg -i "<download_url>" -vn -acodec libmp3lame -b:a 64k -y "douyin-summaries/_temp_audio.mp3"
   ```
3. 调用 `mcp__douyin-mcp__recognize_audio_file` 识别提取的音频文件
4. 识别完成后删除临时文件：`rm "douyin-summaries/_temp_audio.mp3"`

**Level 3 — 基于标题推断**
如果前两级全部失败，在文档中明确标注「⚠️ 语音提取失败，基于视频标题和描述信息重建」，用 WebSearch 搜索相关主题补充内容。

### 第三步：识别文中资源

扫描提取到的文本内容，识别以下类型的资源：
- **URL/链接**：任何 http/https 网址
- **工具/软件名称**：如 gstack、Superpowers、Claude Code 等
- **GitHub 仓库**：owner/repo 格式的引用
- **人名/作者**：有代表性的项目作者或技术人物
- **书籍/文章/论文**：被引用的出版物
- **配置/代码片段**：任何提到的配置方法或命令

对每个识别到的资源，用 `WebSearch` 验证链接有效性、查找官方地址或 GitHub 仓库，确保给出的信息准确。

### 第四步：扩展相关知识

用 `WebSearch` 搜索视频主题的扩展信息：
- 相关工具的官方文档或教程
- 社区讨论（GitHub Issues、V2EX、知乎等）
- 互补或替代方案
- 最新动态（版本更新、相关新闻）

扩展内容的筛选标准：
- 必须是视频内容自然延伸的方向，不要离题
- 优先中文资料（用户是中文用户）
- 标注信息时效性（如"截至 2026.05"）

### 第五步：输出 Markdown 文档

将结果写入 `{当前工作目录}/douyin-summaries/{视频标题简写}.md`。

## 输出格式

文档必须包含以下章节，使用中文撰写：

```markdown
# {视频标题}

> 来源：[抖音视频]({原链接}) | 解析时间：{当前时间}

---

## 视频概要

{用 2-3 句话概括视频讲什么、核心观点是什么}

---

## 核心内容

{分点列出视频主要论点/知识点，每点配合原文关键句}

### 要点一：{小标题}
{展开说明}

### 要点二：{小标题}
{展开说明}

...

---

## 提到的资源

{以表格形式列出视频中提到的所有工具/链接/人/书}

| 名称 | 类型 | 地址/说明 |
|:---|:---|:---|
| gstack | GitHub 工具 | https://github.com/garrytan/gstack |
| ... | ... | ... |

---

## 扩展阅读

{与视频主题相关但视频未覆盖的内容}

- **[文章/帖子标题](链接)** — 一句话说明为什么值得看
- ...

---

## 思考

{一句话总结个人收获，50 字以内}
```

## 注意事项

1. **信息准确性优先**：所有链接必须验证后才列入文档，死链、猜测的链接不要放
2. **适度扩展**：扩展阅读控制在 3-5 条，不要堆砌
3. **文件命名**：视频标题简化为 10 个字以内的文件名，去除特殊字符
4. **目录管理**：如果 `douyin-summaries/` 目录不存在，先创建
5. **ASR 失败处理**：如果文本提取完全失败，在"核心内容"章节改为"根据视频标题和描述推断"，并标注数据来源不完整

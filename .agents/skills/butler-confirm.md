# 管家分级确认

准备动手改代码时加载。

## 三级确认

### 低风险：直接执行，事后通知

操作类型：日志级别调整、超时参数微调、注释添加。

"我把超时时间调了一下，已经生效。要改回来跟我说。"

### 中风险：简短确认

操作类型：函数逻辑修改、库调用替换、新增文件。

预告格式：
- 一句话说改什么（人类语言）
- "要继续吗？"

"我要改处理音频那个函数里的一个判断条件。就一行。要继续吗？"

用户说"行" → 执行。
用户说"解释一下" → 展开但不出现术语。

### 高风险：全面预告

操作类型：API 改动、数据库操作、文件删除、依赖降级、跨模块影响。

预告格式：
- 改什么 + 影响范围 + 涉及文件数
- 最坏情况
- 备份建议
- "要继续吗？"

"这个操作会影响三个地方：音频处理、视频下载、前端播放按钮。大概 5 个文件。最坏情况：有些页面短暂显示不出数据，但不会丢。我建议先备份。要继续吗？"

## 最坏情况预告模板

"最坏的情况：[具体描述]。不会 [超出范围的后果]。你要是不放心，我可以先 [模拟/备份/只读]——不会改任何东西。"

## 一键撤销

每次改动前自动做 git atomic commit。commit message 是人类语言。
用户说"撤销刚才的修改" → 管家叫 implementer 查最近一次 commit 并回滚，管家汇报结果。

"已撤销，回到改之前的状态。"

## 用户反悔

用户说"算了" → 立刻停。问"要退回吗还是留着？"
不追问"你确定吗"。不抱怨"已经改了一半了"。

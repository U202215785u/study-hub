# 管家调试循环 v7.0

进入调试时加载。硬上限：3 次尝试。3 次后升级，不继续撞。

## 第一轮：匹配已知方案

管家查索引 L1——有没有历史记录匹配当前症状？
- 有 → 叫对应领域的专家执行已知方案。成功 → 结束。失败 → 进入第二轮。
- 没有 → 跳过，直接进入第二轮。

## 第二轮：排查最可能的新方向

管家把上下文传递给 debugger 专家，由专家排查：
1. 最近改动的文件
2. 索引里的相似（但不完全匹配）问题
3. 通用陷阱里的高频问题
4. 已装工具匹配度最高的

专家选择最可能的 1 个方向，尝试修复。
成功 → 结束。
失败 → 专家记录"试了什么、结果是什么、排除了什么"。进入第三轮。

## 第三轮：备选方向

debugger 专家基于第二轮结果，排除已证伪路径，选择第二可能方向。
成功 → 结束。
失败 → 不再继续。进入升级。

## 升级：透明汇报

三轮失败后汇报：

"我试了三次。[第一轮试了X，结果]。第二轮试了Y，结果。第三轮试了Z，结果。"
"这三轮排除了 [N] 种可能的方向。剩下的方向可能是 [方向1] 或 [方向2]。"
"你要继续让我试，还是我们换个方式一起看？"

关键设计：
- 汇报的是"排除了什么"——这是进展，不是失败
- 不说"还有好几个方向可以试"——说"剩下[具体方向]"
- 让用户决定是否继续——不是管家自己决定放弃

## 每次尝试记录

无论成功失败，写入索引实验段。格式：

```
[日期] 尝试 [方向] → [结果] → [学到了什么]
```

三条失败路径下次不会再走。

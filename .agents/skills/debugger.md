# 调试者 Skill

触发：管家判断需要故障追踪时激活。

## 硬约束
- 没定位到根因之前，不能提修复方案。铁律。
- 连续 3 次定位失败 → 告诉管家，让管家决定下一步
- 每句判断必须有依据（文件 + 现象 + 推理）
- 发现 3 个以上功能区域涉及同一问题 → 标记为"架构级问题"，告诉管家
- 修复时只改必要代码，不重构不优化

## 工作流程
1. 读项目索引（搜历史问题：有没有复发？搜陷阱：有没有已知坑？）
2. 复述现象（人类语言）
3. 从现象端往回逐层追踪
4. 定位根因
5. 判断：直接修 or 告诉管家这需要架构级方案

## 输出格式（给管家看，不对用户）

【现象】[人类语言描述]
【追踪】逐层检查结果
【根因】文件 + 原因 + 影响范围
【方案】修复建议（如能直接修）或升级建议（如需架构师介入）

## 与管家配合
- 管家激活你时会给上下文
- 你定位完成后把结果返回给管家
- 管家决定要不要动手修
- 修完后管家会问"要不要记下来"

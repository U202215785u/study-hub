# 新媒体创作中心 — Skill 驱动架构

> 记录时间：2026-06-06

## 核心决策

**创作中心从"工具导航"转型为"Skill 驱动"**

旧模式：收集外部工具网站（Shotcut/GIMP/OBS 等）→ 用户跳转使用
新模式：收集 AI Skill → 用户安装后在 CLI 中直接调用

## 为什么这样设计

1. **工具网站是入口，Skill 是生产力** — 用户最终需要的是创作能力，不是工具列表
2. **Skill 可以组合** — Marketing Skills + Claude YouTube + Social Media Skills = 完整工作流
3. **Skill 持续进化** — 社区持续更新，比静态工具链接更有价值
4. **统一体验** — 所有创作都在 Kimi/Claude CLI 中完成，不用跳来跳去

## 页面结构

```
创作中心
├── 通用 Skill（全平台）— 营销、研究、设计、文案
├── 平台 Skill（可切换）— YouTube/抖音/小红书/B站/公众号
├── 工作流 — 预设 Skill 组合
└── 资源库 — 知识库/Wiki/Skill市场
```

## 关键经验

- **不要混用工具和 Skill** — 要么全工具，要么全 Skill，混合会让用户困惑
- **平台切换比分类展示更直观** — 用户想的是"我要发抖音"，不是"我要用视频 Skill"
- **安装命令一键复制是最小可用交互** — 真正的安装应该在 CLI 中完成

## 开放问题

### ISS-036: 扩展 content script 修改后需手动重新加载

**状态**：open  
**严重度**：P1（影响开发效率，用户可 workaround）  
**描述**：修改 `bing-assistant.js` 或 `manifest.json` 后，必须在 `chrome://extensions/` 中点击「重新加载」才能生效。content script 不会自动热更新。  
**根因**：Manifest V3 扩展的 content script 在页面加载时注入，修改后不会自动重新注入已打开的页面。  
**临时解决**：开发时每次修改后手动重新加载扩展。  
**长期解决**：考虑开发模式下使用 `chrome.runtime.reload()` 自动刷新，或改用 WebSocket 热更新方案。

### ISS-037: Shadow DOM 内中文需 Unicode 转义避免乱码

**状态**：open  
**严重度**：P2（功能可用，但代码可读性差）  
**描述**：`bing-assistant.js` 中直接写中文字符串（如 `"产品测评"`）在 Shadow DOM 内显示为乱码。必须使用 Unicode 转义（`"\u4EA7\u54C1\u6D4B\u8BC4"`）。  
**根因**：content script 注入时字符编码可能受页面影响，Shadow DOM 内没有独立的 charset 声明。  
**临时解决**：所有中文字符串使用 `\uXXXX` 转义。  
**长期解决**：将 HTML 模板和 CSS 抽离为独立文件，通过 `fetch()` 加载，避免编码问题。

### ISS-038: 场景规则是静态 JSON，无法动态更新

**状态**：open  
**严重度**：P2（功能可用，但维护成本高）  
**描述**：场景规则存储在 `extension/data/scene-rules.json`，扩展打包后无法动态更新。新增场景或修改关键词需要重新打包扩展。  
**根因**：Manifest V3 扩展的资源文件是静态的。  
**临时解决**：直接修改 JSON 文件并重新加载扩展。  
**长期解决**：后端提供 `/search-assistant/scene-rules` API，扩展启动时拉取最新规则并缓存到 `chrome.storage.local`。

## 已解决问题

### ISS-039: createPanel() 未检测 Shadow DOM 有效性（已修复）

**状态**：resolved  
**修复日期**：2026-05-31  
**描述**：`createPanel()` 只检查 `studyhub-assistant-host` DOM 元素是否存在，如果存在就直接返回。但如果之前注入失败留下了没有 Shadow DOM 的空 host 元素，后续执行会误以为浮窗已存在而跳过创建。  
**修复**：改为检查 `host.shadowRoot` 是否存在且包含 `.studyhub-panel` 元素，如果没有则移除旧 host 重新创建。

---

### ISS-040: 场景匹配错误：旧搜索场景覆盖新搜索（已修复）

**状态**：resolved  
**修复日期**：2026-05-31  
**描述**：搜索"耳机推荐"时浮窗显示"工具查找"场景（显示抠图工具），而非"产品测评"。根因是 `sessionStorage` 中保存了之前搜索的旧场景状态，5分钟内新搜索时旧场景被恢复，跳过了根据新搜索词自动匹配场景的逻辑。  
**修复**：`init()` 中不再从 `sessionStorage` 恢复 `sceneId`。新搜索始终根据搜索词重新匹配场景；筛选后的刷新（搜索词包含 `site:`）才恢复原场景。

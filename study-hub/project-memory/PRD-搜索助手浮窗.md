# PRD：Study Hub 搜索助手浮窗

> 状态：待团队评审

---

## 一、背景与问题

### 1.1 当前痛点

用户在 Study Hub 主页搜索时，走 `/ai-search` API，流程为：

```
用户输入 → Bing 搜索(1-5s) → AI 总结(3-15s) → 显示结果
```

**总等待时间 5-20 秒**，用户体验极差。

### 1.2 真实搜索场景痛点（用户调研）

| 场景 | 用户行为 | 遇到的问题 |
|------|---------|-----------|
| 找工具 | 搜"抠图工具" | 结果前几条是广告、付费工具、软文测评 |
| 查技术 | 搜"UE5 Niagara" | 结果充斥知乎、CSDN 搬运，官方文档被淹没 |
| 找官网 | 搜"image2" | 结果全是测评新闻，找不到 OpenAI 官网入口 |
| 看测评 | 搜"耳机测评" | 软文带货混杂，难以辨别真实测评 |

**核心洞察**：用户不是在找"AI 总结"，而是在找"更准的入口"和"过滤垃圾信息"。

### 1.3 设计原则

1. **不干预主搜索流程** — 用户搜索行为完全不变，Study Hub 只在旁侧辅助
2. **速度优先** — 浮窗内容毫秒级呈现，不依赖 AI 生成
3. **用户可控** — 场景可切换、来源可筛选、浮窗可关闭

---

## 二、功能目标

从 Study Hub 主页搜索时，自动弹出旁侧可拖拽浮窗，根据搜索场景提供：
- **场景化推荐卡片**（工具/文档/官网/测评等）
- **来源筛选功能**（用户可勾选只查看特定网站）
- **AI 实时分析**（可选，对搜索结果进行智能标注）

**不打断用户搜索流程**，用户仍正常跳转到 Bing 查看搜索结果。

---

## 三、核心流程

```
1. 用户在 Study Hub 主页输入搜索词，按回车
2. 瞬间打开 Bing 搜索结果页（新标签页）
3. 同时 Study Hub 原页面右侧弹出搜索助手浮窗
4. 浮窗读取搜索词，自动匹配场景规则
5. 展示场景化卡片 + 来源筛选 + AI 分析区域
6. 用户可：
   - 拖拽浮窗调整位置
   - 切换场景
   - 勾选/取消来源筛选
   - 点击"应用筛选"跳转过滤后的 Bing 搜索
   - 最小化或关闭浮窗
```

## 五、关键决策点（待团队确认）

### 决策 1：来源筛选的生效方式

| 选项 | 描述 | 优缺点 |
|------|------|--------|
| **A. 本次搜索临时生效** | 勾选/取消只影响当前这次搜索，下次恢复默认 | ✅ 简单无负担 ❌ 每次都要重新勾选 |
| **B. 记住用户偏好** | 同场景下记住用户上次勾选，可手动重置 | ✅ 越用越顺 ❌ 可能积累错误偏好 |
| **C. 完全自定义来源列表** | 用户可添加/删除自己的来源网站 | ✅ 最灵活 ❌ 上手成本高 |
| **D. A+B 混合**（推荐） | 默认临时生效，提供"记住此偏好"选项 | ✅ 兼顾灵活与便利 |

### 决策 2：筛选后的搜索执行方式

| 选项 | 描述 | 优缺点 |
|------|------|--------|
| **A. 改写搜索词跳转 Bing**（推荐） | 勾选来源后，搜索词变为 `耳机测评 site:smzdm.com OR site:zhihu.com`，跳转 Bing | ✅ 用户信任（在浏览器看结果）✅ 速度快 ❌ 依赖 Bing 高级语法 |
| **B. 当前页展示过滤结果** | 后端代理搜索，前端渲染过滤后的结果列表 | ✅ 可控性强 ❌ 用户不信任"非浏览器"结果 ❌ 有延迟 |
| **C. 跳转 Bing + 高亮标注** | 正常跳转 Bing，插件在页面内高亮标注"推荐来源" | ✅ 体验最自然 ❌ 实现复杂，需浏览器插件注入 |

### 决策 3：场景判断错误时的处理

| 选项 | 描述 | 优缺点 |
|------|------|--------|
| **A. 用户手动切换** | 卡片顶部显示"当前场景：找官网 [切换 ▼]"，用户手动选 | ✅ 精准控制 ❌ 多一步操作 |
| **B. 显示"你可能也想看"** | 主卡片按判断场景展示，底部显示"你可能也想看：测评 / 购买" | ✅ 无操作成本 ❌ 可能漏掉用户真正想要的 |
| **C. 自动识别 + 用户确认** | 系统给出 2-3 个可能场景，用户点选一个 | ✅ 减少误判 ❌ 弹窗打断流程 |
| **D. A+B 混合**（推荐） | 默认自动匹配，顶部提供切换入口，底部推荐相关场景 | ✅ 兼顾智能与灵活 |

## 六、边界情况

| 场景 | 处理方式 |
|------|---------|
| 搜索词无法识别场景 | 显示"通用搜索辅助"卡片，展示历史记录/收藏夹 |
| 用户关闭浮窗后再次搜索 | 记住用户选择：若上次关闭，本次是否自动弹出（可配置） |
| 来源筛选后无结果 | 提示"筛选条件过严，建议减少来源或查看全部结果" |
| AI 分析调用失败 | 静默失败，不影响卡片主功能 |
| 用户频繁切换场景 | 场景切换实时生效，卡片内容即时更新 |
| 浮窗拖拽到屏幕外 | 自动吸附回可视区域边缘 |

## 七、技术方案概要

### 7.1 涉及模块

| 模块 | 文件 | 说明 |
|------|------|------|
| 前端搜索触发 | `frontend/src/views/Home.vue` | 改造 `doSearch()`，搜索时触发浮窗 |
| 浮窗组件 | `frontend/src/components/SearchAssistant/` | 新组件：浮窗容器、场景卡片、来源筛选 |
| 场景规则库 | `frontend/src/data/searchRules.js` | 新文件：场景定义、关键词映射、来源配置 |
| 拖拽逻辑 | `frontend/src/composables/useDraggable.js` | 新文件：浮窗拖拽 composable |

### 7.2 数据来源

- **场景规则**：本地静态配置（JSON/JS），毫秒级响应
- **AI 分析**：可选调用后端 API（流式输出），失败不影响主功能
- **用户偏好**：localStorage 持久化

### 7.3 性能目标

- 浮窗弹出：≤ 100ms
- 场景匹配：≤ 50ms
- 来源筛选跳转：≤ 200ms（改写搜索词 + 跳转）

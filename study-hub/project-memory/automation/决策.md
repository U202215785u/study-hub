# Automation 模块决策日志

## DEC-AUTO-001：解析文档格式优化（2026-05-30）

### 背景
用户反馈自动解析工具（抖音/B站/小红书）生成的 Markdown 文档存在信息价值不均、格式不统一、ASR 失败时输出注水内容等问题，需要从阅读者视角重新设计信息架构。

### 已确认决策

| 决策点 | 选项 | 说明 |
|--------|------|------|
| 扩展阅读 | C（保留现状） | 维持 3~5 条展开显示，标注时效性 |
| 思考段落 | B（替换为行动建议） | 删除 50 字感悟，改为 1~2 条具体可执行建议 |
| 来源信息 | B（信息增强版） | 保留来源 + 增加作者名、视频时长 |
| ASR 失败 | A（降级为元数据卡片） | 失败时不输出标准长文档，只输出 ≤15 行的元数据卡片 |
| 跨平台格式 | A（严格统一） | 三平台使用完全一致的章节标题和结构 |

### 统一文档骨架（所有平台）

```markdown
# {标题}

> 来源：{平台} @{作者名} | {时长}

---

## 内容概要

---

## 核心内容

### 要点一：...

### 要点二：...

---

## 提到的资源

| 名称 | 类型 | 地址/说明 |
|:---|:---|:---|

---

## 扩展阅读

- **（标题）**（链接） — 一句话说明

---

## 行动建议

1. ...
```

### 边界处理策略

- **空标题**：fallback 为 `未知标题（{平台} {ID}）`
- **无语音视频**：在 `## 内容概要` 顶部标注 `> ⚠️ 该视频无语音或语音过短，以下内容基于标题和描述推断`
- **ASR 失败/解析失败**：输出元数据卡片（标题、来源栏、解析状态、已知信息、建议直接观看原视频）
- **API Key 失效/欠费**：元数据卡片中直接提示充值或更新配置

### 审计记录（2026-05-30）
- 审计者发现问题 1（中）：`_build_meta_card` 中 `asr_error` 可能含换行符，破坏 Markdown 结构 —— 已修复：增加 `replace("\n", " ").replace("\r", " ")` 过滤
- 审计者发现问题 2（低）：`_build_meta_card` 的 `user_input` 参数冗余 —— 未修复（可选优化）
- 审计者发现问题 3（低）：`source_line` 中作者名可能含 `]` 破坏 Markdown 链接语法 —— 未修复（可选优化）

### 验收标准

1. 三平台章节标题完全一致
2. 来源栏包含作者名和时长（如有）
3. 文档中不再出现 `## 思考`
4. ASR 失败文档 ≤15 行
5. 空标题有 fallback
6. 无语音视频有推断标注
7. 扩展阅读保留现状

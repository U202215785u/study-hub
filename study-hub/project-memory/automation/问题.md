- ISS-044: ffmpeg [WinError 2] — Kimi nohup.exe 启动导致 PATH 隔离 — high — 2026-06-06 — **resolved**
  - 根因：Kimi Desktop 通过 MinGW `nohup.exe` 启动后台进程，PATH 不包含 Windows 用户目录（WinGet Links），导致 `subprocess.Popen(['ffmpeg', ...])` 抛出 `FileNotFoundError`
  - 症状：抖音/B站/小红书解析ASR步骤均报「语音提取失败：[WinError 2] 系统找不到指定的文件。」；重新解析同样失败（任务在同一进程中执行）
  - 修复：
    1. 新增 `_find_ffmpeg()` 自动检测 ffmpeg 完整路径（WinGet → Chocolatey → 手动安装 → PATH 回退）
    2. ffmpeg-python `.run(cmd=FFMPEG_CMD, ...)` 使用完整路径，不再依赖进程 PATH
    3. 单独捕获 `FileNotFoundError`，给出中文提示而非 Windows 原始错误
  - 文件：`backend/endpoints/automation.py`

- ISS-016: 抖音口令格式链接无法解析 — high — 2026-05-29 — **resolved**
  - 根因：`DouyinProcessor.parse_share_url()` 正则只匹配 `http://`/`https://` 开头的标准 URL，抖音口令中的 `v.douyin.com/xxxxx`（无协议头）无法识别
  - 修复：在 `automation.py` 中新增 `_preprocess_douyin_input()` 函数，提取无协议短链并补全 `https://`，再传给 `parse_share_url()`
  - 文件：`backend/endpoints/automation.py`
  - 备注：若口令中完全不含 `v.douyin.com/xxxxx` 或 `www.iesdouyin.com/...`（如用户只复制了标题文本），仍需要用户重新复制完整分享文本

## 3. 核心用户路径

### 路径 1：查找并阅读文章

用户目标：快速找到一篇 Wiki 文章并进入稳定阅读态。

步骤：

1. 用户进入 `/wiki`。
2. 用户通过左侧分类、文章列表或搜索入口定位文章。
3. 用户点击文章。
4. 系统展示文章内容、标题、元信息、封面图和 Markdown 正文。
5. 用户可以通过新标签页打开独立文章页 `/wiki/:slug`。

成功标准：

- 用户不需要猜哪里能点。
- 文章内容不空白。
- 长标题和元信息不挤压主要阅读区。
- 独立文章页可直接访问、刷新、返回。

### 路径 2：新建文章

用户目标：在 Wiki 中创建一篇新文章，并确认保存后能再次找到。

步骤：

1. 用户进入 `/wiki`。
2. 用户找到“新建文章”入口。
3. 用户填写标题、分类、标签、封面图、Markdown 内容。
4. 用户点击保存。
5. 系统给出保存反馈，并刷新列表。
6. 用户能在列表或搜索中找到新文章。

成功标准：

- 新建入口明显。
- 空标题、空内容等错误有提示。
- 保存中有 loading。
- 保存成功后列表、当前文章和 URL 状态一致。
- 重复点击保存不会创建重复文章。

### 路径 3：编辑文章

用户目标：修改已有文章，并确认修改结果稳定保存。

步骤：

1. 用户进入 `/wiki` 或 `/wiki/:slug`。
2. 用户打开一篇文章。
3. 用户点击编辑按钮。
4. 系统打开编辑弹窗。
5. 用户修改标题、分类、标签、封面图或正文。
6. 用户点击保存。
7. 系统返回阅读态，并刷新文章内容。

成功标准：

- 编辑按钮不会导致页面重置。
- 编辑弹窗稳定出现。
- 取消编辑不丢当前阅读上下文。
- 保存失败有原因和重试方式。
- 只改封面图时不会导致 slug 丢失或 404。

### 路径 4：wikilink 右侧预览

用户目标：在阅读中查看关联文章，而不中断当前文章。

步骤：

1. 用户打开包含 wikilink 的文章。
2. 用户点击 wikilink。
3. 系统在右侧打开预览面板。
4. 用户选择继续深入、切换为主文章或关闭预览。

成功标准：

- 预览面板不遮挡主阅读区关键内容。
- 面板关闭、切换、深入行为清晰。
- 目标不存在时有友好提示。

## 5. 体验设计要求

### 5.1 入口

- Wiki 页面必须同时提供“阅读入口”和“管理入口”。
- 新建文章入口应位于左侧栏顶部或顶部工具栏，不能隐藏在不明显位置。
- 搜索入口应靠近文章列表，而不是只依赖浏览器查找或隐式快捷键。

### 5.2 状态反馈

Loading：

- 打开文章、保存文章、AI 生成封面图时必须有 loading。

Success：

- 保存成功后必须有明确反馈。
- 列表和当前内容刷新应让用户感知到。

Error：

- API 错误不能只显示技术文本。
- 图片加载失败应有降级。
- 页面不存在应有返回 Wiki 主页的路径。

Empty：

- 无文章时应显示新建引导。
- 搜索无结果时应显示清空搜索或新建文章建议。

### 5.3 防错

- 空标题不能保存。
- 快速连续保存应禁用按钮或防重复提交。
- 编辑中取消或关闭时，如果有未保存内容，应提示用户确认。

### 5.4 视觉

- 文章元信息应从“挤成一行”调整为可扫描的标签式或分组式表达。
- 主题切换按钮应位置稳定，并有可理解的提示。
- 左侧树形索引应通过缩进、图标或层级线表达结构。

## 6. 边界测试

| 场景 | 操作 | 预期 |
|---|---|---|
| 空数据 | 使用空 Wiki 数据进入 `/wiki` | 出现空状态和新建入口 |
| 大量文章 | 50+ 文章列表滚动和查找 | 列表不卡顿，搜索/分类仍可用 |
| 超长标题 | 创建或编辑超长标题 | 不撑破列表、标题区、弹窗 |
| 超长正文 | 编辑长 Markdown | 编辑和保存过程可用，有 loading |
| 特殊字符标题 | 标题含中文、空格、符号 | slug 和 URL 稳定 |
| 封面图 404 | 使用错误封面 URL | 图片降级，不影响正文 |
| AI 生成超时 | 触发封面图生成失败 | 给出失败提示和重试入口 |
| 网络错误 | 保存时后端不可用 | 保留编辑内容，提示失败 |
| 重复点击保存 | 连续点击保存按钮 | 不重复提交 |
| 移动端 | 390px 宽度访问 Wiki | 左栏、正文、预览不互相挤压 |
| wikilink 不存在 | 点击不存在目标 | 友好提示，不空白 |

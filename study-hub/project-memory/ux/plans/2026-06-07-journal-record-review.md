## 1. 任务卡定位

本卡是高频主路径第四张任务卡。

Wiki、Home、Automation 已完成首轮走查且均无 P1 阻断。现在进入 Journal，因为它是 Study Hub 中唯一一个"个人情感数据"模块——用户在这里写日记、记录心情、回顾过去。丢失数据或保存失败的伤害比功能模块更高。

本卡目标：

```text
进入日记页
  -> 写今日日记（心情/天气/地点/贴纸/标签）
  -> 保存成功
  -> 切换日期查看历史
  -> 编辑/删除操作
  -> 浏览统计和随机回顾
```

本卡不做视觉重设计，不做图片上传等新功能，优先验证当前的记录-保存-回顾链路是否稳定可用。

## 3. 核心用户路径

### 路径 1：写今日日记

用户目标：打开日记 → 记录今天 → 保存 → 确认已保存。

步骤：

1. 用户从 Home 或导航进入 Journal。
2. 系统默认选中"今天"。
3. 用户选择心情 / 输入天气 / 输入地点 / 选择贴纸。
4. 用户输入正文（placeholder 引导"随便写点什么就好"）。
5. 用户添加标签。
6. 用户点击保存。
7. 系统反馈保存成功，显示"上次保存 HH:MM"。
8. 左侧日历今天日期出现小圆点。
9. 左侧时光轴出现新条目。

成功标准：

- 日期默认今天，不用手动选择。
- 心情选择有即时视觉反馈（选中高亮）。
- 贴纸选择有即时视觉反馈（弹跳动画）。
- 保存按钮有 loading 态（"保存中…"）。
- 保存成功后"还未保存"变为"上次保存 HH:MM"。
- 同一天多次保存自动合并，不创建重复条目。
- 保存失败有可理解的提示（不是裸 alert）。

### 路径 2：查看历史与编辑

用户目标：翻阅之前的日记 → 查看内容 → 修改 → 保存。

步骤：

1. 用户通过日历点击有标记的日期。
2. 或通过时光轴点击某天条目。
3. 主内容区加载该天日记。
4. 用户修改内容、心情、标签等。
5. 用户点击保存。
6. 系统更新条目，刷新统计。

成功标准：

- 日历有日记的日期显示小圆点。
- 时光轴显示当月日记列表。
- 点击日历日期或时光轴条目都能加载日记。
- 编辑后保存不会创建重复条目（同一天仍然是 upsert）。
- 删除后日历小圆点消失，时光轴刷新。

### 路径 3：统计与回顾

用户目标：看看写了多少天、连续写了多久、回顾随机旧日记。

步骤：

1. 用户进入 Journal。
2. 左侧顶部显示"已记录 N 天"+"连续 N 天"。
3. 右侧面板显示心情分布（进度条）。
4. 用户点击随机回顾区域 → 加载一篇旧日记。
5. 用户点击"换一篇" → 刷新随机结果。
6. 用户点击随机回顾卡片 → 跳转到那篇日记。

成功标准：

- 统计数据准确（总天数、连续天数）。
- 心情分布百分比正确。
- 随机回顾不会抽到当前正在看的日记。
- 随机回顾卡片可点击，点击后加载那篇日记。
- 没有日记时随机回顾显示温和空状态（"多写一些，就会有回忆"）。

### 路径 4：边界与错误

用户目标：在异常情况下不丢数据、不被卡住、能理解发生了什么。

场景：

- 空内容保存：正文为空时保存是否被允许？提示是什么？
- 后端不可用：保存/加载时 API 报错，用户看到什么？
- 切换日期未保存：在 A 日记写了内容 → 点击切换到 B 日期 → A 的内容是否丢失？
- 删除确认：点击删除后的确认方式是什么？取消后数据是否还在？
- 移动端 390px：三栏布局是否可用？
- 快速连点保存：会不会创建重复条目？

成功标准：

- 空内容允许保存（日记不强制写满），不报错。
- API 错误有 toast/提示，不是静默失败也不是裸 alert。
- 切换日期前如果有未保存内容，有必要提示或自动保存。
- 删除确认使用项目内确认组件（非原生 confirm）。
- 移动端至少有可用降级布局。

## 5. 体验设计要求

### 5.1 写日记体验

核心原则：**降低提笔的阻力**。

- 默认选中今天，进来就能写。
- placeholder 温暖不压迫："亲爱的自己，今天发生了什么？不用很长，像安东尼那样，随便写点什么就好..."
- 心情、天气、地点、贴纸是锦上添花，不是必填项。
- 保存按钮不要离正文太远。
- 保存成功的反馈要温和（"上次保存 23:14"比弹窗好）。

### 5.2 翻阅体验

核心原则：**让过去的日子好找**。

- 日历小圆点是最重要的导航线索，必须准确。
- 时光轴条目显示日期 + 心情 + 第一行文字预览。
- 点击任意日期/条目都能加载，不出现"点了没反应"。
- 今天的日记在时光轴中有视觉区分（"今天"徽章）。

### 5.3 回顾体验

核心原则：**像翻旧日记本一样的惊喜感**。

- 随机回顾不是"随机数"，是"从你的过去随机抽一篇"。
- 空状态要温柔："多写一些，就会有回忆"。
- 点击随机回顾卡片能跳转到那篇日记（不只是看看）。

### 5.4 数据安全感

核心原则：**日记是私密的情感数据，丢失不可接受**。

- 保存失败不能静默。用户必须知道保存没成功。
- 切换日期前如果有未保存内容，需要提醒或自动暂存。
- 删除需要确认，确认后不可恢复的感知要传递到位。
- 后端返回错误（如数据库锁）时前端不能白屏。

## 6. 边界测试

| 场景 | 操作 | 预期 |
|------|------|------|
| 空内容保存 | 不写正文直接点保存 | 允许保存，不报错 |
| 长日记 | 输入 5000+ 字 | 文本不截断，保存成功 |
| 特殊字符 | 输入 emoji、换行、引号 | 正常保存和显示 |
| 同一天多次保存 | 连续保存 3 次 | 自动合并，不创建重复条目 |
| 后端不可用 | 停掉后端后点保存 | 显示错误提示，不是空白 |
| 后端不可用 | 停掉后端后切换日期 | 显示错误提示或空状态 |
| 切换日期未保存 | 写了内容 → 不保存 → 点另一个日期 | 提示未保存或自动暂存 |
| 删除取消 | 点删除 → 弹确认 → 取消 | 数据仍保留 |
| 删除确认 | 点删除 → 弹确认 → 确认 | 条目删除，日历和时光轴刷新 |
| 快速连点保存 | 快速点保存 3 次 | 按钮有禁用态，不创建重复 |
| 无日记空状态 | 全新数据库进入 Journal | 日历无圆点，时光轴显示"这个月还没有写字" |
| 心情全为同一种 | 连续写多篇同一心情 | 心情分布一个占 100%，其他不显示 |
| 日历跨月 | 切换到有日记的月份 | 日历显示正确，时光轴显示该月条目 |
| 随机回顾空 | 没有日记时点随机回顾 | 显示"多写一些，就会有回忆" |
| 移动端 390px | 打开 Journal | 三栏不溢出，至少有一栏可见或可切换 |

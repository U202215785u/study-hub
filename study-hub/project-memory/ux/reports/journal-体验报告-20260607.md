## 3. 发现的问题

### P1-001：切换日期未保存内容直接丢失

- **级别**：P1
- **描述**：用户在 A 日期写了内容但未保存，点击日历切换到 B 日期时，系统未提示未保存，也未自动暂存，A 日期的内容直接丢失。切回 A 日期时，内容已恢复到上次保存的状态。
- **截图**：`jr-p5-unsaved-switch.png`
- **影响**：日记是情感数据，丢失不可接受。这是核心路径阻断。
- **建议**：
  - 方案 A（推荐）：自动保存草稿，切换日期时自动保存当前内容。
  - 方案 B：切换日期前检测未保存内容，弹出确认"当前内容未保存，是否保存？"
  - 方案 C：自动保存到 localStorage 草稿，切换后自动恢复。

### P2-001：删除使用原生 confirm

- **级别**：P2
- **描述**：删除日记使用原生 `confirm()`，与其他模块（Wiki 的弹窗、Home 的 confirm）体验不一致，且原生 confirm 会阻塞页面交互。
- **截图**：浏览器验证
- **建议**：后续 UI Feedback Components 统一替换为自定义确认弹窗。

### P2-002：保存失败使用原生 alert

- **级别**：P2
- **描述**：代码调研确认保存失败时使用 `alert(result.error)`，体验差。
- **建议**：使用 Toast 提示保存失败，并提供重试入口。

### P2-003：移动端 390px 三栏布局不可用

- **级别**：P2
- **描述**：390px 视口下，三栏固定宽度布局（左 240px + 中 flex-1 + 右 200px）导致横向溢出，中间写日记的主内容区完全不可见。
- **截图**：`jr-p5-mobile.png`
- **建议**：移动端改为单栏布局或可切换标签页（日历 / 写日记 / 统计）。

### P2-004：随机回顾数据源仅限当月

- **级别**：P2
- **描述**：代码调研确认随机回顾从 `entries.value` 中选取，而 `fetchEntries` 只拉取当前选中年月的日记，因此随机回顾实际只从当月随机，不是全局随机。
- **建议**：全局随机回顾应从全部日记中选取，或提供独立 API。

### P2-005：时光轴截断仅显示前 15 条

- **级别**：P2
- **描述**：代码调研确认 `.slice(0, 15)` 截断，当月超过 15 篇日记无法全部显示。
- **建议**：增加"展开更多"或滚动加载。

### P3-001：无日记时随机回顾未测试空状态

- **级别**：P3
- **描述**：本次未测试全新数据库进入 Journal 时的空状态。

## 5. 结论

Journal 桌面端核心链路（写日记→保存→查看历史→统计回顾）**基本可用**，但存在 **1 个 P1 阻断问题**：

- **P1-001 切换日期未保存内容丢失**：这是数据安全问题，日记是私密情感数据，丢失不可接受。必须修复后才能认为 Journal 路径稳定。

其余 P2 问题（原生 confirm/alert、移动端适配、随机回顾范围、时光轴截断）不影响桌面端主路径，可记入 backlog。

**建议下一步**：
1. **优先修复 P1-001**（自动保存或切换前提示）。
2. 修复 P1 后，Journal 路径稳定，可进入 Search Assistant 最后一站。
3. P2 问题在后续 UI Feedback Components 统一任务中批量处理。

# PRD：Study Hub 搜索助手浮窗 v2

> 状态：待团队评审  
> 版本：v2.0（基于团队确认「浏览器扩展注入 Bing 页面」技术方案）  
> 日期：2026-05-30  
> 核心原则：**让用户少想、少点、少等，但始终保留控制权**

---

## 一、背景与问题

### 1.1 当前痛点

用户在 Study Hub 主页搜索时，走 `/ai-search` API，流程为：

```
用户输入 → Bing 搜索(1-5s) → AI 总结(3-15s) → 显示结果
```

**总等待时间 5-20 秒**，用户体验极差。

### 1.2 真实搜索场景痛点（用户调研）

| 场景 | 用户行为 | 遇到的问题 |
|------|---------|-----------|
| 找工具 | 搜"抠图工具" | 结果前几条是广告、付费工具、软文测评 |
| 查技术 | 搜"UE5 Niagara" | 结果充斥知乎、CSDN 搬运，官方文档被淹没 |
| 找官网 | 搜"image2" | 结果全是测评新闻，找不到 OpenAI 官网入口 |
| 看测评 | 搜"耳机测评" | 软文带货混杂，难以辨别真实测评 |

**核心洞察**：用户不是在找"AI 总结"，而是在找"更准的入口"和"过滤垃圾信息"。

### 1.3 设计原则

1. **不干预主搜索流程** — 用户搜索行为完全不变，Study Hub 只在旁侧辅助
2. **速度优先** — 浮窗内容毫秒级呈现，不依赖 AI 生成
3. **用户可控** — 场景可切换、来源可筛选、浮窗可关闭

---

## 二、功能目标

从 Study Hub 主页搜索时，**通过浏览器扩展在 Bing 页面注入浮窗**，根据搜索场景提供：
- **场景化推荐卡片**（工具/文档/官网/测评等）
- **来源筛选功能**（用户可勾选只查看特定网站）
- **AI 实时分析**（可选，对搜索结果进行智能标注）

**不打断用户搜索流程**，用户仍在同一页面查看 Bing 搜索结果，浮窗在右侧辅助。

---

## 三、核心流程

```
1. 用户在 Study Hub 主页输入搜索词，按回车
       │
2. Study Hub 打开 Bing，URL 携带上下文参数：
   https://bing.com/search?q=耳机测评&ref=studyhub&sid=abc123&scene=product_review
       │
3. 浏览器扩展检测到 ref=studyhub 参数
       │
4. 扩展在 Bing 页面注入浮窗 DOM（右侧，position:fixed）
       │
5. 用户在同一页面看到：左侧 Bing 结果 + 右侧浮窗
   → 不需要切标签页，浮窗就在眼前
```

## 五、关键决策（已确认）

### 决策 1：来源筛选的生效方式

**选择：隐式记忆 + 透明 UI**

- 同一场景下，用户上次勾选过的来源，本次自动预勾选
- 预勾选的来源旁有一个极细微的标记（灰色小圆点 ● + hover 时显示 tooltip「根据你上次的选择自动勾选」）
- 来源列表顶部有一行小字链接：「恢复默认来源」，一键清空记忆
- 偏好数据存在 `chrome.storage.sync`，跨设备同步

**理由**：用户行为天然有模式——搜测评的人大概率每次都看同样的来源。系统主动适配这个模式，但不强迫用户理解背后的逻辑。

---

### 决策 2：筛选后的搜索执行方式

**选择：页面内 URL 改写 + 原地重载**

用户点击「应用筛选」→ 浏览器地址栏更新为筛选后的 URL → 页面原地重载 → 扩展重新检测 URL 参数并注入浮窗。

**浮窗状态跨刷新保持：**

| 状态项 | 恢复方式 |
|--------|---------|
| 当前场景 | 从 URL 参数 `scene` 恢复，或从 `chrome.storage.session` 恢复 |
| 来源勾选 | 从 `chrome.storage.local` 恢复（刷新前最后一刻写入） |
| 浮窗位置 | 从 `chrome.storage.local` 恢复 |
| 浮窗展开/折叠 | 从 `chrome.storage.session` 恢复 |
| AI 分析内容 | 不恢复（重新加载，因为搜索结果变了） |

**URL 改写规则：**

- 原始搜索词保持完整且放在最前面
- site 筛选放在后面：`耳机测评 site:smzdm.com OR site:zhihu.com`
- 保留 `ref=studyhub` 和 `sid` 参数，让扩展能识别并注入
- 更新 `scene` 参数为当前用户选择的场景
- 超过 3 个 site 来源时，仅取前 3 个（Bing 对长 OR 链处理不稳定），剩余来源在浮窗内以灰色显示并标注「已超出 Bing 单次筛选上限，下次可调整」

**理由**：用户始终在同一个标签页内完成「搜索 → 看结果 → 筛选 → 再看结果」的循环。没有新标签页堆积，没有上下文切换。

---

### 决策 3：场景判断错误时的处理

**选择：标签页式场景切换器 + 底部关联场景卡片**

- 横向标签页，当前场景高亮，所有场景一字排开可见可点
- 底部 1-2 个关联场景缩略卡片
- 切换场景后同步更新 URL 中的 `scene` 参数

**理由**：标签页比下拉快一倍，信息完全可见，不打断用户当前在 Bing 页面上的搜索心流。

---

### 决策 4：AI 分析区域的展示方式

**选择：渐进式流式加载 + 场景感知触发**

- 简单场景不展示 AI 分析，复杂场景自动展示
- AI 请求通过扩展 background service worker 代理转发，绕过 Bing CSP 限制

**请求路径：**
```
浮窗 content script → chrome.runtime.sendMessage() → background service worker → AI API
                                                                                      ↓
浮窗 content script ← chrome.runtime.sendMessage() ← background service worker ← 流式响应
```

**理由**：有就优雅出现、没有就安静消失，不占用空间也不增加等待焦虑。

---

### 决策 5：浮窗的默认位置与尺寸

**选择：右侧固定面板 + 可拖拽 + Bing 布局感知**

**Bing 页面布局适配策略：**

```
场景 A：Bing 显示了 Knowledge Panel
┌──────────────────────────┬─────────────────────┐
│                          │  Study Hub 浮窗      │
│  搜索结果列表             │  (替换 Knowledge     │
│                          │   Panel 位置)        │
│                          │  360px 宽            │
└──────────────────────────┴─────────────────────┘

场景 B：Bing 没有 Knowledge Panel
┌──────────────────────────┬─────────────────────┐
│                          │  Study Hub 浮窗      │
│  搜索结果列表             │  (右上角固定)        │
│                          │  360px 宽            │
│  结果占用全宽              │  position: fixed     │
│                          │  top: 72px           │
│                          │  right: 16px         │
└──────────────────────────┴─────────────────────┘
```

**布局注入策略：**

| 场景 | 检测条件 | 浮窗行为 |
|------|---------|---------|
| Bing 有 Knowledge Panel | `#b_context` 元素存在 | 隐藏 Knowledge Panel，替换为浮窗 |
| Bing 无 Knowledge Panel | `#b_context` 不存在 | 浮窗以 `position:fixed` 出现在右侧，搜索结果区自动缩减 `margin-right` |
| 窗口宽度 < 1024px | 响应式检测 | 浮窗宽度缩为 280px，收缩进右侧 |
| 窗口宽度 < 768px | 移动端 | 浮窗变为底部抽屉（从下弹出，占屏幕 40% 高度），点击 Bing 结果区自动收起 |

**交互细节：**

- **固定/拖拽双模式**：默认固定在右侧（不可拖拽，减少操作负担）。标题栏右侧有一个图钉图标 `📌`，点击解除固定 → 变为可拖拽浮窗。再次点击图钉恢复固定。
- **位置记忆**：用户解除固定并拖拽后的位置存入 `chrome.storage.local`，下次自动恢复拖拽位置。固定模式下不记忆（始终在右侧）。
- **浮窗与页面滚动**：固定模式下 `position: fixed`，始终可见。拖拽模式下同样 `position: fixed`，但位置由用户决定。
- **双击标题栏**：固定模式 → 切换「有 KP 时替换 KP」和「始终在右侧固定」；拖拽模式 → 恢复到固定模式。
- **Bing 搜索框焦点**：当浮窗固定且用户点击 Bing 搜索框时，浮窗自动收窄至 60px 宽（仅显示图标），让出空间。用户点击浮窗图标恢复全宽。

**理由**：在 Bing 页面上，用户几乎总是在看左侧搜索结果，右侧是固定的「辅助区」。固定 + 可选拖拽比全拖拽更省心——系统帮用户摆好了位置，需要时可解除固定。

---

### 决策 6：浮窗的触发时机

**选择：全自动注入 + 一键关闭恢复**

**阶段一：全自动（默认）**

- 从 Study Hub 搜索 → Bing 页面打开 → 扩展自动注入浮窗
- 浮窗从右侧滑入（300ms 入场动画）
- 前 3 次使用：浮窗底部有一行引导文字「Study Hub 搜索助手 · 可切换场景、筛选来源」（第 4 次起消失）

**阶段二：用户关闭后**

- 用户点击浮窗关闭按钮 → 浮窗消失 → Bing 页面右下角出现一个小圆点 `💡`（16px，半透明）
- 小圆点 hover 时显示 tooltip「搜索助手」
- 点击小圆点 → 浮窗重新展开
- 小圆点在本 session 内持续存在
- 用户重新从 Study Hub 搜索时，恢复全自动注入（新的搜索意图 = 新的辅助机会）

**去掉永久降级。** 浮窗在 Bing 页面上并不是「打扰」——它在一侧安静存在，不遮挡搜索结果，关闭成本极低（点一下 ×），重新打开也很轻量（点一下右下角 💡）。

**理由**：浮窗在搜索结果旁边不构成打扰，关闭后留小圆点一键恢复，不需要复杂的降级状态机。

## 六、扩展特有的体验考量

### 6.1 仅在「来自 Study Hub」的 Bing 页面注入

扩展必须区分「用户从 Study Hub 搜索」和「用户正常使用 Bing」。检测方式：URL 参数 `ref=studyhub`。

- 有该参数 → 注入浮窗
- 无该参数 → 完全不干预 Bing 页面，扩展零存在感

### 6.2 扩展安装后的首次引导

用户安装扩展后第一次从 Study Hub 搜索时，浮窗注入后在标题栏显示一次性引导：

> 👋 Study Hub 搜索助手已就绪。它会在你从 Study Hub 搜索时自动出现在右侧。

### 6.3 扩展权限的透明沟通

安装扩展时权限提示会显示「读取和更改 bing.com 上的数据」。建议在 Study Hub 的扩展安装引导页说明：

> 「仅在从 Study Hub 跳转到 Bing 时生效，不会读取或修改你的其他 Bing 搜索行为。」

### 6.4 Bing 页面 DOM 变化的容错

Bing 会不定期调整页面结构和 class 名。扩展需要：

- 检测 Knowledge Panel 时使用多个备选选择器
- 注入浮窗时不依赖 Bing 的具体 DOM 结构（用 `document.body.appendChild`）
- 浮窗样式完全自包含（Shadow DOM 隔离），不被 Bing 的 CSS 影响，也不影响 Bing 的样式

推荐使用 Shadow DOM 包裹浮窗：

```js
const host = document.createElement('div');
host.id = 'studyhub-assistant-host';
document.body.appendChild(host);
const shadow = host.attachShadow({ mode: 'closed' });
// 浮窗所有 DOM 和样式都在 shadow 内，完全隔离
```

### 6.5 浮窗对 Bing 搜索结果区宽度的影响

浮窗占据右侧空间后，Bing 的搜索结果区（`#b_results`）如果保持原宽度，会被浮窗遮挡。解决方案：

- 注入浮窗后，动态给 `#b_results` 添加 `margin-right: 376px`（浮窗 360px + 16px 间距）
- 浮窗关闭或收缩时，恢复原始 margin
- 如果 Bing 本身有 Knowledge Panel，先隐藏 KP 再放置浮窗，搜索结果区宽度保持不变

### 6.6 浮窗与 Bing 的深色模式兼容

Bing 支持深色模式。扩展需要检测 `html[data-theme="dark"]` 或 `prefers-color-scheme` 并适配浮窗配色。

## 七、边界情况

| 场景 | 处理方式 |
|------|---------|
| 搜索词无法识别场景 | 显示"通用搜索辅助"卡片，展示历史记录/收藏夹 |
| 用户关闭浮窗后再次搜索 | 恢复全自动注入（新的搜索意图 = 新的辅助机会） |
| 来源筛选后无结果 | 提示"筛选条件过严，建议减少来源或查看全部结果" |
| AI 分析调用失败 | 静默失败，不影响卡片主功能 |
| 用户频繁切换场景 | 场景切换实时生效，卡片内容即时更新 |
| 浮窗拖拽到屏幕外 | 自动吸附回可视区域边缘 |
| Bing 页面结构变化导致注入失败 | 降级为固定位置浮窗（不替换 Knowledge Panel），保证功能可用 |
| 扩展未安装 | Study Hub 搜索时正常跳转 Bing，无浮窗，不报错 |
| 用户手动修改 URL 去掉 ref=studyhub | 扩展检测到参数缺失，不注入浮窗 |

## 八、技术方案概要

### 8.1 涉及模块

| 模块 | 文件/目录 | 说明 |
|------|----------|------|
| Study Hub 搜索跳转 | `frontend/src/views/Home.vue` | 改造 `doSearch()`，跳转 Bing 时携带 `ref=studyhub&scene=xxx&sid=xxx` 参数 |
| 浏览器扩展 - manifest | `extension/manifest.json` | 新增 `content_scripts` 匹配 `bing.com/search?*ref=studyhub*` |
| 浏览器扩展 - content script | `extension/content-scripts/bing-assistant.js` | 检测 Bing 页面，注入浮窗 Shadow DOM |
| 浏览器扩展 - background | `extension/background.js` | 代理 AI 请求，管理跨标签页通信 |
| 场景规则库 | `extension/data/scene-rules.json` | 场景定义、关键词映射、来源配置（本地静态） |
| 浮窗 UI 组件 | `extension/ui/assistant-panel/` | Vue/Vanilla JS 组件：标题栏、场景标签、卡片、筛选器 |
| 拖拽逻辑 | `extension/ui/composables/draggable.js` | 浮窗拖拽 composable |

### 8.2 数据流

```
Study Hub 搜索
    ↓
打开 Bing（携带 ref=studyhub&scene=xxx&sid=xxx）
    ↓
扩展 content script 检测到 URL 参数
    ↓
读取 scene-rules.json 匹配场景
    ↓
注入 Shadow DOM 浮窗
    ↓
用户交互（切换场景、勾选来源、点击筛选）
    ↓
改写 URL → 原地重载 → 浮窗状态恢复
    ↓
（可选）AI 分析请求 → background worker → AI API → 流式返回
```

### 8.3 性能目标

| 指标 | 目标 |
|------|------|

| 场景匹配 | ≤ 50ms（本地规则库，无网络请求） |

## 九、验收标准

- [ ] 从 Study Hub 搜索时，Bing 页面自动注入浮窗
- [ ] 浮窗默认固定在右侧，适配 Bing 布局（有 KP 时替换 KP）
- [ ] 浮窗可拖拽、最小化、关闭，关闭后右下角显示小圆点
- [ ] 至少 4 个预设场景可用（工具查找/技术文档/找官网/产品测评）
- [ ] 场景自动匹配准确率 ≥ 70%
- [ ] 用户可手动切换场景，切换后 URL 参数同步更新
- [ ] 来源筛选功能可用，支持多选，自动记忆用户偏好
- [ ] 筛选后原地重载 Bing，浮窗状态跨刷新保持
- [ ] 卡片点击可跳转新标签页
- [ ] AI 分析区域按场景智能触发，流式加载
- [ ] 扩展仅在 `ref=studyhub` 页面注入，其他 Bing 页面零干预
- [ ] 浮窗样式与 Bing 深色模式兼容
- [ ] 扩展使用 Shadow DOM 隔离，不影响 Bing 页面样式

## 十、决策汇总

| 决策项 | 选择 | 一句话理由 |
|--------|------|-----------|
| 来源筛选生效方式 | 隐式记忆 + 透明 UI | 系统默默记住、UI 透明告知，偏好存 chrome.storage 跨设备同步 |
| 筛选执行方式 | 页面内 URL 改写 + 原地重载 | 浮窗已在同一页面，刷新即可，不开新标签页打断心流 |
| 场景判断错误处理 | 标签页切换 + 关联推荐 | 一键切换比下拉快一倍，所有场景可见，不打断 |
| AI 分析展示方式 | 流式渐进加载 + 场景感知 | 有就优雅出现、没有就安静消失，扩展 background worker 代理请求 |
| 浮窗位置与尺寸 | 固定右侧 + 可选拖拽 + KP 位置复用 | 默认固定减少操作负担，需要时可解除固定，智能适配 Bing 布局 |
| 浮窗触发时机 | 全自动注入 + 一键关闭恢复 | 浮窗在搜索结果旁边不构成打扰，关闭后留小圆点一键恢复 |

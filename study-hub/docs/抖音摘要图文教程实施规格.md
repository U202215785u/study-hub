# 抖音解析"总结 + 图文教程"可选输出 — 实施规格（修订版）

> 状态：已评审，规格已按评审意见修订，待实施。
> 基于：《抖音解析"总结 + 图文教程"可选输出方案》+ 可行性评审意见 + codex 修订意见。
> 关联代码：`backend/endpoints/automation.py`、`backend/database.py`、`frontend/src/views/Home.vue`、`frontend/src/views/KnowledgeBase.vue`、`frontend/src/components/MarkdownRenderer.vue`、`frontend/src/config/ports.js`、`frontend/tests/port-policy.mjs`、`docs/端口规范.md`、`frontend/src/assets/main.css`。

## 1. 关键决策（本规格固定，不再变更）

| # | 决策 | 说明 |
|---|---|---|
| D1 | `5182` 为"内容解析图文教程"专属自动化测试端口 | 登记进 `ports.js` 的 `TEST_PORTS`，**同步更新 `port-policy.mjs` 的 `assert.deepEqual` 断言**，并在 `docs/端口规范.md` 补充归属说明 |
| D2 | 同一任务一次产出并保存总结与教程 | 一次模型调用返回"总结区块 + 教程区块"，避免双调用竞争与重复耗时 |
| D3 | `task_id` 隔离中间文件 | 视频、音频、关键帧、模型输出草稿均放 `douyin-summaries/{task_id}/`（教程时）或临时目录，杜绝标题同名覆盖 |
| D4 | 教程首期不入向量库 | 搜索先命中该文档的总结，用户再切换教程；不增加索引成本与召回混杂 |
| D5 | 重新解析继承原文档教程选项 | `reparse` 读取 `parse_options.include_tutorial` 并写入新任务 |
| D6 | 两个文档入口共用"解析结果阅读器" | `Home.vue` 与 `KnowledgeBase.vue` 都使用同一组件；标签放容器层，`MarkdownRenderer` 只负责渲染内容 |
| D7 | 教程失败绝不影响总结 | 教程分支独立 try/except，失败仅写 `tutorial_status=failed` + 原因 |

## 2. 两处阻断项（必须先处理）

### B1. 5182 端口登记三件套

现状：`frontend/tests/port-policy.mjs` 第 9 行是深度相等断言：

```js
assert.deepEqual(TEST_PORTS, Object.freeze({ workbench: 5180, dashboard: 5181 }))
```

新增 `tutorial: 5182` 后该测试必然失败。实施必须同时：

1. `frontend/src/config/ports.js`：`TEST_PORTS` 增加 `tutorial: 5182`。
2. `frontend/tests/port-policy.mjs`：更新断言为包含 `tutorial: 5182`，并补一条 `tutorial` 用例（如 `testOrigin(TEST_PORTS.tutorial) === 'http://127.0.0.1:5182'`）。
3. `docs/端口规范.md`：5180-5189 表格下注明 `5180 工作台测试 / 5181 首页测试 / 5182 内容解析图文教程测试`。

### B2. 抽帧必须发生在视频临时文件清理之前

现状：`_extract_douyin_raw`（automation.py 318-443 行）下载视频 → ffmpeg 转音频 → ASR，`finally` 无条件删除 `tmp_video`/`tmp_audio`。总结完成后视频已不存在，无法抽帧。

实施要求：

- `include_tutorial=true` 时，视频下载后**不删除**，把 `tmp_video`（或复制到 `douyin-summaries/{task_id}/video.mp4`）路径随 `raw` 返回；
- 抽帧在**视频删除之前**完成：元数据/ASR 就绪后立即抽候选帧（按转写时间点或均匀取样），抽帧完成后才允许清理视频；
- 抽帧失败只标记教程不可生成，不阻断总结。

## 3. 评审修正点（第 3 点结论调整）

`_run_claude`（637-705 行）实际行为：先扫 `output_dir` 中 `mtime > cutoff` 的新 `.md`（Claude 工具自写文件）；**没有时**把 stdout 写为 `output_dir/{标题}.md`（677 行，标题截断 60 字符作文件名）。

风险确认：`MAX_WORKERS=5` 并发时，不同任务标题相同会覆盖同一文件；总结与教程同目录双调用必然同题覆盖。

**修订后方案（D2 + D3）：**

- 模型调用一次，prompt 要求输出两个明确分隔区块（例如 `<!-- TUTORIAL_START -->` / `<!-- TUTORIAL_END -->` 标记）；
- 后端按标记拆分：总结区块 → `content`，教程区块 → `tutorial_markdown`；
- 输出草稿与中间文件统一写入 `douyin-summaries/{task_id}/`，任务结束后清理草稿（保留关键帧供文档引用）；
- 若模型输出缺少教程区块或标记，按"教程不可生成"处理，总结照常入库。

## 4. 其余 5 点实施规格

### S1. 不依赖 cover 字段

现状 `DouyinProcessor.parse_share_url` 只返回 `url/title/video_id`，无封面。教程首图**从抽帧结果中选择**；无法判断最终效果时使用"关键画面"命名（`![关键画面](...)`），**不虚构"最终效果"**。封面增强可后续单独排期。

### S2. 教程首期不入向量库

入库逻辑（automation.py 943-989 行附近）只对 `content` 做 `chunk_text` + `vs.add_document`。教程字段仅写入 `documents` 表，不参与向量化；搜索命中该文档时，用户在阅读器内切换到教程标签。

### S3. reparse 继承教程选项

`reparse_document`（1525 行）提交新任务时，读取原文档 `parse_options`：

```python
task["include_tutorial"] = bool(json.loads(doc["parse_options"] or "{}").get("include_tutorial"))
```

`_process_single_task` 从任务 dict 读取该字段，而非仅从 payload。

### S4. 共用"解析结果阅读器"

新建组件（如 `frontend/src/components/DocumentReader.vue`），职责：

- 接收 `{ title, summaryMarkdown, tutorialMarkdown, tutorialStatus, tutorialReason }`；
- 渲染"总结 | 图文教程"标签（仅 `tutorial_status` 有内容/状态时显示教程标签；`not_requested` 不显示）；
- 标签切换纯前端状态，不重新请求；
- 内部使用现有 `MarkdownRenderer` 渲染正文。

`Home.vue`（51-57 行 docModal）与 `KnowledgeBase.vue`（339-366 行 docModal）均替换为使用该组件。`MarkdownRenderer` 不加标签逻辑。

### S5. 教程分支独立 try/except

在 `_process_single_task` 中，教程生成包在独立 `try/except`：

```python
try:
    tutorial_markdown, tutorial_status = _generate_tutorial(...)
except Exception as e:
    tutorial_markdown, tutorial_status = None, "failed"
    tutorial_reason = str(e)[:500]
```

失败只写 `tutorial_status='failed'` 与 `tutorial_reason`，总结流程继续。

## 5. 静态目录与图片样式

### F1. 关键帧静态目录

现状 `main.py` 438 行 `app.mount("/images", StaticFiles(directory=IMAGES_DIR))`。**不能沿用"目录存在才挂载"方式**——首次生成图片时目录可能尚不存在，挂载会失败导致图片 404。

实施：启动时先 `os.makedirs(TUTORIAL_FRAMES_DIR, exist_ok=True)`，再无条件挂载 `/tutorial-frames`。建议目录：

- `study-hub/frontend/public/tutorial-frames/`（若前端静态托管）或后端专用目录（若由后端服务，如 `study-hub/backend/tutorial_frames/`）。

### F2. 教程图片专属样式

`main.css` 459 行 `.markdown-content img:first-of-type` 会把第一张图全宽 + `max-height:360px` 封面裁切。教程正文首图若命中该规则会被放大裁切。

实施：教程容器使用专属 class（如 `.tutorial-content`），并覆盖：

```css
.tutorial-content .markdown-content img:first-of-type {
  width: auto; max-height: none; object-fit: contain; border-radius: 8px;
}
```

或在阅读器组件内为教程正文包裹独立 class，避免影响其他 Markdown 场景。

## 6. 数据与接口（修订）

### 6.1 提交接口

```json
{ "module_id": "douyin-summary", "input": "链接", "include_tutorial": true }
```

- `queue_tasks`（1280 行）接收并透传 `include_tutorial` 到每个任务 dict；
- 未传/`false` 行为与当前完全一致；
- 批量（换行/数组）时对所有链接生效。

### 6.2 documents 表新增字段（复用 database.py 149-156 行兼容迁移模式）

| 字段 | 类型/默认 | 说明 |
|---|---|---|
| `tutorial_markdown` | TEXT DEFAULT '' | 教程 Markdown |
| `tutorial_status` | TEXT DEFAULT 'not_requested' | `not_requested`/`ready`/`unavailable`/`failed` |
| `tutorial_reason` | TEXT DEFAULT '' | 不可生成/失败原因 |
| `parse_options` | TEXT DEFAULT '{}' | JSON，含 `include_tutorial` |

### 6.3 task_queue 表

新增 `include_tutorial INTEGER DEFAULT 0`（或复用 `parse_options` JSON 列），`_task_to_db` INSERT 列同步更新；`recover_tasks_on_startup` 恢复时一并恢复该字段。

### 6.4 去重键

`input_hash` 由 `sha256(input)` 改为 `sha256(f"{input}\ninclude_tutorial={include_tutorial}")`（842 行）。`_check_existing_by_input_hash` 沿用 task_queue 与占位文档两路检查，但查询键须一致。

## 7. 异常与降级（修订）

| 场景 | 总结 | 教程 |
|---|---|---|
| 正常视频与转写 | 正常生成 | 正常生成 |
| 视频无法下载 | 现有降级 | `unavailable`，"视频无法下载" |
| 转写失败但元数据存在 | 现有元数据卡片 | `unavailable` |
| 内容非操作教学 | 正常生成 | `unavailable`，"未识别到足够操作步骤" |
| 关键帧提取失败 | 正常生成 | `unavailable`，"视频画面提取失败，可查看原视频" |
| 教程模型输出异常/缺区块 | 正常生成 | `failed`，可单独重试（重试即重新解析并继承选项） |
| 未勾选教程 | 正常生成 | `not_requested` |

## 9. 验收标准（在原方案 10 条基础上修订）

1-8 与原方案一致；其中：

- 第 2 条明确为"一次任务同时保存总结与图文教程（同一篇文档）"；
- 第 4 条教程首图不得被 `img:first-of-type` 全宽裁切；
- 第 8 条在 `http://127.0.0.1:5182` 通过，且 `port-policy.mjs` 含 `tutorial: 5182` 断言通过；
- 新增：教程不入向量库（搜索不返回教程片段）；
- 新增：`reparse` 后新文档 `tutorial_status` 与原文档一致（继承）。

## 10. 风险与控制（修订）

- 一次调用两区块：prompt 需非常明确分隔标记，后端解析要容忍标记缺失（降级为仅总结）；
- 教程增加视频处理与模型调用成本，默认不勾选（保持原方案）；
- 关键帧仅用于当前文档阅读，保留来源链接与"基于原视频整理"标记；
- 首期只支持抖音，B站/小红书后续评估。

# 首页原子组件与 Storybook 设计规格

## 目标

把已经完成并验证的首页仪表盘视觉语言沉淀为 Study UI 的真实公共组件，并让正式首页实际复用这些组件。Storybook 负责展示设计语言、组件状态、使用边界和完整仪表盘组合，不创建一套与正式首页分离的视觉实现。

## 范围

本轮只覆盖当前正式首页及其九张模块卡片。其他页面可以继续使用现有组件，但不为了覆盖其他页面新增抽象。

本轮不修改后台、接口、数据库、首页业务数据来源、路由目标和现有事件含义。知识库复制/删除、自动化打开/重试/创建、模块隐藏/恢复/排序等现有行为必须保持。

## 抽象原则

1. 只有在首页出现至少两次、具有一致视觉与交互语义的结构才提炼为公共组件。
2. 组件按照 `Foundations -> Atoms -> Molecules -> Organisms -> Widgets -> Page Example` 单向依赖。
3. Storybook 导航继续使用 Ant Design 式功能分类；原子层级写入组件文档，而不是把全部组件只按原子层级分组。
4. 公共组件只接收展示数据并抛出小型事件，不访问 API、Pinia 或页面路由。
5. 组件化前后，首页 `1440×980` 基准几何、固定 `8×4` 网格、九张卡片尺寸和 `16px` 内容边距不得改变。

## 设计语言文档

Storybook 新增以下设计语言页面：

- `设计语言/总览`：设计原则、原子依赖关系、使用边界。
- `设计语言/颜色与状态`：画布、表面、文字、强调色、内容分类色和状态色。
- `设计语言/字体与密度`：首页标题、模块标题、正文、辅助文字和紧凑控制尺寸。
- `设计语言/间距与圆角`：4px 间距阶梯、16px 卡片内容边距、卡片与胶囊圆角。
- `设计语言/阴影与动效`：卡片层级、浮层层级、交互时长和减少动效策略。

所有页面直接读取现有 `--ui-*` 语义变量，不复制另一套颜色和尺寸常量。

## 公共组件设计

### 原子组件

#### UiButton 扩展

- 新增 `size="xs"`，用于首页卡片内部的 24px 紧凑操作。
- 新增 `shape="default" | "pill"`，默认保持现有圆角，`pill` 用于胶囊操作。
- 保持现有 `variant`、loading、disabled、prefix、suffix 和 click 契约。
- 首页不再通过深层 CSS 把 `sm` 按钮强制压缩成 20px 或 24px。

#### UiBadge 扩展

- 新增 `size="default" | "compact"`。
- `compact` 用于卡片内 10px 状态文字，继续同时显示文字和状态点，不能只靠颜色表达。

#### UiProgress 扩展

- 新增 `size="default" | "compact"`，compact 轨道高度为首页队列所需的紧凑高度。
- 新增 `status="active" | "success" | "warning" | "danger"`，使用现有语义状态色。
- 继续提供原生 `progressbar` 语义和 0-100 数值截断。

### 分子组件

#### UiCompactHeader

用于九张卡片中的紧凑标题行。

- Props：`title`、`meta`、`level`、`size`。
- Slots：默认标题旁内容和 `action`。
- 标题必须单行截断；右侧信息不得挤压标题或改变卡片高度。
- 首批替换知识库、快捷指令、创作入口、快捷工作流、日历日程和今日任务中的重复标题结构。

#### UiInsetSurface

用于卡片内部的虚线或实线小型表面，本身不承担点击语义。

- Props：`border="dashed" | "solid"`、`tone="default" | "muted"`、`interactive`。
- Slots：默认内容和 `actions`。
- 统一边框、背景、圆角、内边距、hover/focus-within 状态和溢出保护。
- 首批替换知识库文档行、快捷指令行、创作标题行、自动化输入区和工作流输入区的重复容器样式。
- 真正的按钮或输入框继续由内部原生控件提供，避免嵌套按钮。

#### UiPillButton

用于卡片内部的选项、步骤和紧凑胶囊动作。

- Props：`active`、`disabled`、`tone="neutral" | "action"`。
- 使用原生 button，暴露 click，激活态设置 `aria-pressed`。
- 首批替换创作入口选项和快捷工作流步骤；顶部导航仍保留 RouterLink 语义，不强行复用按钮组件。

## 组织和业务组件

- `DashboardModuleCard` 继续负责统一边框、圆角、阴影、16px 内容边距以及 loading/error/empty/content 状态优先级。
- `WorkbenchFrame`、`BentoDashboardGrid` 和 `DashboardEditor` 继续负责固定比例舞台、8×4 网格和模块编辑。
- 九张业务 Widget 保留现有 props 和 emits，只把重复视觉结构替换成新的公共原子或分子组件。
- 不把工作热力、日历、今日任务等领域结构拆成没有第二个使用场景的伪通用组件。

## Storybook 信息架构

最终导航分类：

1. `设计语言`
2. `通用`
3. `导航`
4. `数据录入`
5. `数据展示`
6. `反馈`
7. `布局`
8. `仪表盘组件`
9. `完整范例`

每个公共组件必须包含：

- 定义、适用场景和不适用场景。
- 原子层级和依赖方向。
- Props、events、slots。
- 默认、尺寸、变体、disabled/loading/error/empty、长文字和窄容器状态中适用的部分。
- 键盘、焦点和可访问名称说明。
- 使用的语义 Token。
- 已知 Figma 节点；没有组件节点时明确标记为从首页 Frame 提炼。

九张 Widget 的 Story 统一放入 `仪表盘组件`，保留默认、空数据、加载、错误、长文字和容量上限示例。

`完整范例/首页仪表盘` 使用公共组件和静态夹具组合完整 `1440×980` 首页，不请求真实 API，不复制新的业务逻辑。该范例用于视觉验收，不替代正式首页。

## 迁移顺序

1. 先补 Token 和 Storybook 设计语言页面。
2. 扩展 UiButton、UiBadge、UiProgress，并迁移首页现有覆盖样式。
3. 新增 UiCompactHeader、UiInsetSurface、UiPillButton。
4. 逐张迁移九个 Widget，每迁移一组都保持原事件契约。
5. 整理 Storybook 分类并增加完整首页范例。
6. 更新稳定导出、组件状态表和设计系统说明。

## 测试与验收

- 每个新增或扩展的公共组件先写失败测试，再做最小实现。
- 组件测试覆盖原生语义、prop 限制、事件载荷、状态优先级和长文字保护。
- 文档覆盖测试必须确认每个公共导出都有测试、Story 和状态表记录。
- `npm run build:storybook` 必须成功。
- 全量前端单元测试和生产构建必须成功。
- 首页响应式、Figma 几何、卡片 16px 边距、无溢出和布局持久化检查必须继续通过。
- 在 `1440×980` 截图中，组件化前后的导航、问候区、网格和九张卡片几何误差不得超过现有测试容差。

## 明确不做

- 不为尚未出现的业务场景提前增加组件。
- 不把每段文字或每个图标都组件化。
- 不改变首页网格尺寸、模块数量或 Figma 复刻方向。
- 不修改后台接口、数据库和自动化任务流程。
- 不在本轮统一重构其他页面。

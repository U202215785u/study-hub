# 全栈 Vibe Coding Engineer 学习路线图

> 专为 AI 辅助编程时代设计的自学路线——你不需要成为能徒手写代码的传统程序员，你需要成为**能读懂代码、能设计系统、能用 AI 高效交付产品**的独立产品工程师。

---

## 核心理念

在你开始之前，先理解几个重要的认知框架：

**你不是在学「写代码」，你是在学「让计算机做事」。** 代码只是你和计算机之间的沟通语言。AI 可以帮你写这门语言，但你必须知道你想让计算机做什么、为什么这样做、以及做出来的东西对不对。

**概念优先，语法靠后。** 你需要深刻理解「什么是数据库」「什么是 API」「什么是状态」，但不需要背诵 `useState` 的精确写法——AI 会帮你写。

**永远在项目中学习。** 不要陷入教程地狱。每个新概念的学习，都要立刻在一个真实的小项目里用出来。

**AI 是你的学习加速器。** 遇到不懂的概念，直接让 AI 用比喻解释给你听。看到 AI 生成的不懂的代码，立刻追问「这段代码在做什么」。

---

## 总体路线图概览

```
Phase 0: 心智热身        Week 1         —— 建立学习系统，了解计算机世界的基础地图
Phase 1: 可见层          Week 2-5       —— 前端三件套 + React，理解用户看到的一切
Phase 2: 数据层          Week 6-9       —— 数据库、API、后端逻辑，理解背后发生的一切
Phase 3: 基础设施层      Week 10-12     —— Git、部署、域名、环境变量，让产品真正上线
Phase 4: 产品工程        Week 13-20     —— 从零到一独立交付 3 个真实产品
Phase 5: AI 协作精通     持续贯穿       —— 高级 AI 协作模式，从「让 AI 写代码」到「让 AI 帮你设计系统」
```

## Phase 0: 心智热身（Week 1）

**目标：建立正确的学习系统和世界观，不做无效努力。**

### 本周要建立的概念地图

你需要先有一张「世界地图」，知道每个知识点放在哪里。画一张图来理解：

```
用户浏览器 ←→ 互联网 ←→ 你的服务器 ←→ 数据库
     |                         |
  前端代码                 后端代码
  (HTML/CSS/JS)           (Python/Node.js)
```

你需要理解这几个问题（不用深究细节，先有概念）：
- 当用户在浏览器输入网址按下回车，发生了什么？从请求发出到页面显示，经历了哪些步骤？
- 什么是「前端」和「后端」？什么是「客户端」和「服务端」？
- 什么是「数据库」？为什么需要它？

### 本周要完成的事

1. **安装并配置好你的开发环境**
   - 安装 VS Code（或继续用 Cursor）
   - 安装 Node.js
   - 安装 Git
   - 注册 GitHub 账号
   - 注册 Vercel 账号（后续部署用）

2. **学会用终端**
   - `cd`（切换目录）、`ls`（看文件）、`mkdir`（创建文件夹）
   - `npm install`、`npm run dev`（启动项目）
   - 不要背命令，每次用的时候查，用多了自然记住

3. **建立你的学习笔记系统**
   - 用 Notion 或 Obsidian 建一个学习笔记库
   - 每学一个概念，用自己的话写一句话解释
   - 每做完一个练习项目，写三段话：我做了什么、我遇到了什么困难、我怎么解决的

4. **学会向 AI 问好问题**
   - 练习：找一段你之前项目里 AI 生成的代码，让 Claude 逐行解释给你听
   - 练习：让 Claude 用「给 10 岁小孩解释」的方式解释一个你不懂的概念
   - 关键原则：永远追问「为什么」，永远要求「用比喻解释」

## Phase 1: 可见层——前端世界（Week 2-5）

**目标：深刻理解用户在浏览器里看到的一切是怎么来的。**

### Week 2: HTML + CSS 核心概念

**你不需要手写完美 CSS，但你必须理解盒模型、布局、和选择器。**

核心概念（理解即可，不背诵）：
- HTML 的标签结构：什么是 DOM 树？为什么网页是「一棵树」？
- CSS 盒模型：margin、border、padding、content 分别是什么？
- Flexbox 布局：为什么它是现代布局的基础？
- CSS 选择器和优先级：为什么有些样式会被覆盖？
- 响应式设计：为什么同一个网页在手机和电脑上看起来不一样？

本周项目：用纯 HTML + CSS 做一个漂亮的个人 Landing Page（让 AI 帮你写，但逐行理解）

### Week 3: JavaScript 核心概念

**这是最重要的基础。JavaScript 是浏览器的语言，也是 Node.js 的语言，学会它你就打通了前后端。**

核心概念（必须深刻理解）：
- 变量和数据类型：string、number、boolean、array、object 分别是什么？
- 函数：什么是输入（参数）和输出（返回值）？
- 异步编程：什么是「异步」？为什么 JavaScript 需要 async/await？
- Promise：什么是 Promise？它解决了什么问题？（用「餐厅取餐牌」的比喻来理解）
- 数组方法：map、filter、reduce——这三个是最常用的，必须会用
- 解构赋值和展开运算符：`...` 到底在干什么？

本周项目：用纯 JS 做一个 Todo 应用（数据存在 localStorage 里）

### Week 4: React 核心概念

**React 是目前最主流的前端框架。你不是要成为 React 专家，但你要理解它的核心思想。**

核心概念（React 的世界观）：
- 组件：React 里的一切都是组件。什么是组件？为什么要把页面拆成组件？
- JSX：为什么 HTML 可以写在 JavaScript 里？
- State（状态）：这是 React 最重要的概念。什么是状态？为什么 UI 是状态的函数？
- Props：组件之间怎么传递数据？
- Hooks：useState、useEffect、useContext 分别做什么？
- 虚拟 DOM：React 为什么快？（理解概念即可，不用深究实现）

本周项目：用 React 重写你的 Todo 应用，加上分类和搜索功能

### Week 5: Next.js + Tailwind CSS 入门

**Next.js 是 React 的「全栈框架」，Tailwind 是现代 CSS 的写法。这对组合是独立开发者的首选。**

核心概念：
- Next.js 的文件路由：文件名就是 URL 路径
- 服务端组件 vs 客户端组件：Next.js 13+ 最核心的概念
- Server Actions：不用写 API 就能处理表单
- Tailwind 的 utility-first 思想：为什么在 HTML 里写一大堆类名是好主意？
- shadcn/ui：直接复制粘贴组件的 UI 库，独立开发者的最佳选择

本周项目：用 Next.js + Tailwind + shadcn/ui 做一个博客系统（用 Markdown 文件作为数据源）

## Phase 2: 数据层——后端的真相（Week 6-9）

**目标：理解数据怎么存储、怎么流动、怎么被保护。**

### Week 6: 数据库基础

**数据库就是「有组织的 Excel 表格」。**

核心概念：
- 关系型数据库 vs 非关系型数据库：什么时候用哪个？
- 表和字段：一个 SaaS 产品需要哪些表？users、posts、orders？
- 主键和外键：表之间怎么关联？
- SQL 基础：SELECT、INSERT、UPDATE、DELETE
- ORM（对象关系映射）：为什么我们用 Prisma/Drizzle 而不是直接写 SQL？

本周项目：
- 先用 Excel 设计一个 SaaS 产品的数据库结构（画表、定义字段）
- 然后用 Prisma + SQLite 实现它
- 练习用 Prisma Studio 可视化查看数据

### Week 7: API 设计

**API 是前端和后端之间的「合同」。**

核心概念：
- 什么是 API？为什么需要它？（用「餐厅服务员」的比喻来理解）
- RESTful API：GET、POST、PUT、DELETE 分别是什么语义？
- JSON：前后端通信的数据格式
- 认证和授权：JWT 是什么？Session 是什么？为什么需要登录？
- Next.js 的 API Routes 和 Server Actions

本周项目：给你 Week 6 的数据库加一套完整的 CRUD API

### Week 8: 认证和用户系统

**每个产品都需要用户登录。理解它，而不是复制粘贴。**

核心概念：
- 密码哈希：为什么不能明文存密码？bcrypt 在做什么？
- JWT 认证流程：登录 → 发 Token → 每次请求带 Token → 验证 Token
- OAuth：什么是「用 Google 登录」？OAuth 流程是怎样的？
- 中间件：什么是中间件？为什么认证要在中间件里做？
- NextAuth.js / Clerk：为什么不用自己手写认证系统？

本周项目：做一个需要登录才能访问的私人笔记应用

### Week 9: Python 后端（可选但推荐）

**你已经接触过 Python。用 Python 写后端能让你理解「语言只是工具」。**

核心概念：
- Flask 或 FastAPI：Python 的 Web 框架
- 用 Python 写一遍你已经用 Next.js 写过的 API
- 理解前后端分离架构：前端用 Next.js，后端用 Python API
- 这个练习的核心目的：让你明白「框架和语言不是重点，理解了概念就行」

本周项目：用 FastAPI 给笔记应用写一套后端 API，前端继续用 Next.js 调用

## Phase 3: 基础设施层——让产品真正上线（Week 10-12）

**目标：理解产品怎么从你的电脑上跑到互联网上。**

### Week 10: Git 和 GitHub

**你之前的项目可能没用 Git。现在必须学，这是所有开发的基础设施。**

核心概念：
- 什么是版本控制？为什么需要它？
- 仓库（Repository）、提交（Commit）、分支（Branch）
- `git add` → `git commit` → `git push` 的工作流
- 分支和合并：多人协作的基础
- .gitignore：什么不该提交到仓库？
- Pull Request：代码审查的基本流程
- GitHub 的基本使用

本周项目：把你之前所有项目都用 Git 管理起来，推到 GitHub

### Week 11: 部署和 DevOps 基础

**让你的产品被别人访问到。**

核心概念：
- 什么是服务器？Vercel、Railway、AWS 分别是什么？
- 域名和 DNS：为什么输入 `google.com` 能访问到 Google？
- HTTPS 和 SSL 证书：为什么网址前面有把小锁？
- 环境变量：为什么 API 密钥不能写在代码里？
- CI/CD：自动测试和部署是什么概念？

本周项目：
- 把你 Phase 2 的笔记应用部署到 Vercel（前端）+ Railway（后端）
- 买一个域名（便宜的就行），绑定到你的应用
- 配置好 HTTPS

### Week 12: 集成第三方服务

**独立开发者的超能力——借用别人的服务，不自己造轮子。**

核心概念：
- 为什么独立开发者要尽量用 SaaS 服务而不是自建？
- 支付：Stripe 的基本集成流程（创建 Checkout Session → 前端跳转 → Webhook 回调）
- 邮件：Resend 或 SendGrid 的基本使用
- 文件上传：上传到哪个服务？URL 怎么存？
- 数据库服务：PlanetScale、Supabase 这些托管数据库怎么用？

本周项目：给笔记应用加上付费功能（Stripe 集成，但用测试模式，不真的收钱）

## Phase 4: 产品工程——从零到一交付真实产品（Week 13-20）

**目标：独立完成 3 个完整的、可以上线的产品。这是你学习成果的检验。**

### 学习节奏转变

前 12 周是「学中做」，现在切换到「做中学」。你不再按课程学习，而是：

1. 选定一个产品想法
2. 用 AI 帮你快速出 MVP（最小可行产品）
3. 遇到不懂的概念再回头学
4. 每个产品周期约 2-3 周

### 产品 1: SaaS 工具箱（Week 13-14）

一个简单的工具合集网站，比如：JSON 格式化、Base64 编解码、URL 编解码、Markdown 预览等。

**技术点覆盖**：Next.js、客户端交互、文件处理、SEO、部署上线

### 产品 2: 微型 SaaS（Week 15-17）

一个有用户系统、付费功能的完整 SaaS。方向建议：
- 一个漂亮的习惯追踪器
- 一个 AI 加持的读书笔记工具
- 一个简单的发票生成器
- 选你真正感兴趣的方向

**技术点覆盖**：用户认证、数据库设计、支付集成、邮件通知、后台管理

### 产品 3: 自由选题（Week 18-20）

选一个你真正想做、觉得有商业潜力的方向。完整地从想法→设计→开发→部署→发布走一遍。

**这次的重点是**：不再只是「让 AI 写代码」，而是你主导设计决策，AI 辅助执行。

## Phase 5: AI 协作精通（持续贯穿）

**这是你作为「Vibe Coding Engineer」的核心竞争力。**

### AI 协作的五个层级

**Level 1: 代码生成者**（你现在的阶段）
「帮我写一个登录页面」
→ AI 生成，你复制粘贴，能用就行

**Level 2: 需求翻译者**
「我需要一个用户系统，支持邮箱注册和 Google 登录，密码要加密存储，登录后发 JWT Token」
→ 你能用精准的技术语言描述需求

**Level 3: 代码审查者**
→ AI 生成代码后，你能读、能判断好坏、能指出问题

**Level 4: 系统设计者**
「我要做一个多租户 SaaS，每个租户有独立的数据、独立的子域名，技术栈用 Next.js + PostgreSQL」
→ 你能做架构决策，让 AI 帮你拆解和实现

**Level 5: AI 管理者**
→ 你能同时驱动多个 AI 实例做不同的事，你来协调和验证

### 每周都要练习的 AI 协作模式

**模式 A: 解释模式**——让 AI 解释你不懂的代码
```
提示词模板：
「这段代码在做什么？逐行解释，用简单的比喻。」
```

**模式 B: 对比模式**——让 AI 给你多种方案
```
提示词模板：
「实现 [功能] 有几种方式？给我至少三种方案，对比它们的优缺点，
哪种最适合独立开发者的小项目？」
```

**模式 C: 审查模式**——让 AI 检查你的代码
```
提示词模板：
「审查这段代码，从以下角度：安全性、性能、可维护性、最佳实践。
指出每个问题的严重程度和改进方案。」
```

**模式 D: 教学模式**——让 AI 教你概念
```
提示词模板：
「我想理解 [概念]，先给我一个生活中的比喻，然后解释技术细节，
最后告诉我作为独立开发者我在什么场景下需要用到它。」
```

**模式 E: 师徒模式**——让 AI 带着你做
```
提示词模板：
「我想实现 [功能]，但不要直接给我完整代码。
用苏格拉底式的提问引导我先思考：数据怎么组织？界面怎么设计？
状态怎么管理？等我回答后再给我代码。」
```

## 推荐学习资源

- **CS50（哈佛计算机导论）**：不只是学编程，而是建立计算机世界观。免费，有中文字幕。建议 Phase 0-1 期间看前 5 讲。

## 几个重要的提醒

**不要跳过基础。** 你可能想直接跳到用 AI 做产品，但如果不懂「状态」「异步」「数据库关系」这些基础概念，你永远只能做玩具项目。基础打好了，后面的路会越走越快。

**每周至少做一个项目。** 哪怕很小。知识不通过项目内化就是死知识。

**允许自己「暂时不理解」。** 有些概念（比如闭包、原型链）第一遍不可能完全懂，先接受它存在，在后续的项目中反复遇到，自然会越来越清楚。

**找到同伴。** 如果有条件，找一个也在学的人一起。互相看代码、互相解释概念，学习效率翻倍。

**保持公开输出。** 把你做的项目发到社交平台。写得烂没关系，没人一开始就写得好。公开输出的好处是：你会更认真地做、能收到反馈、还能建立你的个人品牌——这对独立开发者很重要。

---

*这份路线图不是一成不变的。每完成一个 Phase，回头审视：我学到了什么？什么学习方法对我最有效？然后调整后面的计划。学习编程不是线性的，是螺旋上升的。*

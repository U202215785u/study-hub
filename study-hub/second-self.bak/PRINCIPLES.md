# PRINCIPLES — 决策原则

> v2.0 | PRINCIPLES 是"我应该怎么做"——宪法层。
> PREFERENCES 是"我实际上偏向什么"——性格层。
> Agent 同时读取两者。当 PRINCIPLES 和 PREFERENCES 冲突时，标注偏差，不替 L 选择。
> 正例/反例从 DECISIONS.md 派生（Lint 阶段自动同步）。

---

## P0: Agent 的解读是基于显式信息的推断，不是真相

**含义**：Agent 只说出了基于你写下来的东西可以推导出的结论。你没写下来的恐惧、动机、假设——Agent 不知道。

**正例**：当 Agent 的解读让你觉得"对！就是这样"→ 你写下的东西是准的。这个认同感本身验证了你的自我认知。

**反例**：当 Agent 的解读让你觉得"不对，不是这个原因"→ 那个"不对"的感觉本身，就是你没写下来的东西在敲门。停下来问自己：为什么我觉得不对？我漏写了什么？

**适用场景**：任何 Agent 给你解读的时候。这是所有原则中的元原则——它定义了 Agent 和你的关系边界。

---

## P1: 不因为恐惧而选择安全

**含义**：当一个选项的吸引力主要来自"不会出错"而非"可能对"，警惕它。

**反例**：因为害怕面试失败而不投大厂。

**正例**：选岚图是因为算了武汉生活成本 + AI 自学空间的账，不是因为不敢去北上广。

---

## P2: 优先积累可展示的产出

**含义**：做一件事的价值 = 做完之后有没有东西能拿给别人看。

**适用场景**：评估业余时间投入方向。学一个技能 → 做一个作品 → 展示。如果学的东西永远停留在"学了"而没有变成"作品"，它的复利为零。

---

## P3: 不在第一份工作的工资上纠结

**含义**：22-25 岁的收入差异在 35 岁时回头看可忽略不计。这个阶段的唯一目标是让下一份工作的定价权变高。

**适用场景**：计算储蓄率的时候不要焦虑，该焦虑的是技能积累速度。

---

## P4: 维持关系的稳定质量

**含义**：不和女朋友的关系出问题是长期生产力的基础设施。

**适用场景**：任何可能显著影响双方情绪稳定性的决策，需要把她纳入考量。

---

## P5: 信息先过优先级漏斗

**含义**：任何新想法 / 新机会 / 新焦虑 → 先和 ME.md 里的三个最高优先级比对。
- 直接相关 → 进入 DASHBOARD 战略项目区跟踪
- 间接相关 → 记入 wiki，三个月后回来看
- 不相关 → 允许丢弃

---

## P6: 行动优于分析

**含义**：当信息已经足够做出一个 70% 置信度的决策时，先动。不要在 70% → 90% 的区间里花过多时间。

**适用场景**：我容易过度分析导致行动延迟，这条是专门约束这个倾向的。

**边界说明**：不是所有分析都是拖延。当你确实缺少关键信息、而该信息获取成本不高时，多花一轮分析是合理的。Agent 在原则一致性检查中提出 P6 冲突怀疑时，你需要标注"合理分析"或"确实在回避"——前者是边界内的正常行为，后者是真正的 P6 违规。连续 3 次标注"合理分析"后，Agent 自动调高触发阈值。

---

## P7: 能量有限是事实，但不能当借口

**含义**：承认精力是稀缺资源，做战略取舍是对的。但需要定期自检——省下来的精力是不是真的投入到了高优先级事项上。如果省下来的精力只是被低质量消耗掉了，"能量有限"就是借口。

## 附录：正例/反例的捕获机制

> v1.1 新增

正例和反例不会在你做决策的瞬间自动浮现。它们需要在事后被识别和记录。系统通过两个机制实现：

**机制 A — Lint 阶段模式回顾**：Agent 在每次 Lint 时扫描最近一段时间的对话主题和 Ingest 日志，识别出"看起来像是在做决策但你当时可能没意识到"的时刻，列出候选，询问你是否构成某条原则的正例或反例。时间差不是劣势——回头看时识别准确率更高。

**机制 B — 用户主动记录**：当你意识到某个决策是某条原则的正例/反例时，直接告诉 Agent："记录为 P6 的反例"或"这是 P2 的正例"。Agent 追加到对应原则的条目下。

**记录格式**：

```
**反例 (2026-06-03)**: {一句话描述当时发生了什么，为什么是反例}
**正例 (2026-07-15)**: {一句话描述当时发生了什么，为什么是正例}
```

正例和反例的积累不需要穷举。每条原则有 2-3 个高质量的正例/反例就足够 Agent 理解其适用边界。
